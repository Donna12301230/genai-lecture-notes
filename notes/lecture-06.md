## 01. 跑本地端的模型（投影片 P2–P13，影片約 0:04 起）

### 1.0 為什麼要在自己電腦上跑模型？

💬 老師補充：
- 到職場上，很可能會被要求跑**地端（本地端）模型**。
- 想做實驗，或是「養龍蝦」（把一整台電腦交給 AI 代理人去跑）時，**燒 token 的速度非常快**——能不能在自己電腦上跑語言模型，就不用付這筆 token 費用？

### 1.1 兩種選擇：LM Studio 與 Ollama（P3）

| 工具 | 說明 |
|---|---|
| **LM Studio** | 圖形介面，下載模型就能聊 |
| **Ollama** | 指令列操作，💬 老師覺得**稍微有彈性一點** |

- 兩種都**要記得更新**（新模型推出時，舊版常常跑不動）。

### 1.2 可以考慮的開源型 LLM（P4）

| 等級 | 模型 | 備註 |
|---|---|---|
| 超大型 | MiMo-V2.6-Pro 1000B、GLM-5.3 753B、Kimi K3 2800B | **一般人基本上跑不動**；**都是中國的** |
| 中型 | gpt-oss-120B | |
| 中小型 | Qwen3.8 27B、Muse Glimmer 30B、Gemma4 31B／26B | |
| 超輕量 | K2 Horizon 7B、Gemma4 12B、Qwen3.5 4B／9B | |

💬 老師補充：
- **超大型**：目前仍是「越大越厲害」，表現接近 ChatGPT、Claude 等商業模型。排行榜上表現好的超大型開源模型幾乎都是中國的（中文訓練資料比較多），安全性問題後面再談（見 2.7）。雖然開源、理論上能自己跑，但要花非常大一筆錢，除非家裡真的很有錢。
- **中型**：代表是 **gpt-oss**。OpenAI 自 GPT-2 之後、進入 ChatGPT 時代就再也沒開源過，gpt-oss 是 ChatGPT 出現後 OpenAI **第一個開源的語言模型**，120B 並不小。要有相當好的電腦設備才跑得動。
- **中小型**：一般家裡或實驗室「還不錯規格」的電腦大概可以跑。
- **超輕量**：資源非常有限，但仍想在自己電腦上跑語言模型的選擇。
- **B = Billion（十億）**。當年 1.5B（15 億參數）的 GPT-2 已被說是「大到可怕」；現在「超輕量」的 4B（40 億參數）就已經比 GPT-2 大了。

### 1.3 怎麼找適當的模型？兩大 AI 評測（P5）

| 評測 | 網址 | 方式 |
|---|---|---|
| **Arena AI**（競技場） | <https://arena.ai/> | 使用者盲測：同一個問題給兩個模型回答，**使用者選比較喜歡的**（真人評測） |
| **Artificial Analysis** | <https://artificialanalysis.ai/> | 不斷更換評測方法、討論出各項目的評分比例，較**有系統、科學**的評法 |

💬 老師補充：**排名是很粗的資訊**

- 就像畢業後要申請美國的學校，第一步當然先看排名，但排名只能告訴你「大概不錯」。**最重要的是適不適合你。**
- **傳統 benchmark（例如收集數學競試題目算正確率）的問題：**
  1. 大家都知道會考什麼，所以模型都會**加強訓練做這類題目**，不知道是不是真的厲害。
  2. 就算很會做數學競賽題，**關我們什麼事？**（老師：我是數學系的，我都覺得關我什麼事。）
  3. 不要幻想 95% 正確的 AI 可以當免費家教：**我們不會的時候，分不出它說的對還是錯**；而且答案對的那 95% 裡，**做法也可能是錯的**。
- **Arena 的優點與盲點**：剛推出時讓人驚豔（真人評測）；但使用者沒受過「改考卷」的訓練，**比較阿諛奉承的模型容易被選**，尖銳批評你想法的模型反而被嫌棄 → 有人類主觀在裡面。不過它仍是兩大重要評測之一。
- 兩者都有缺點，但好處是**可以只看開源模型**。老師的粉專有分別介紹兩者的優缺點。

### 1.4 跑模型的機器考量（P6–P11）

**NVIDIA GPU 的 VRAM（P6）**

| GPU | VRAM |
|---|---|
| RTX 5090 | 32GB |
| RTX 4090 | 24GB |
| H100 | 80GB |
| H800 | 80GB |

💬 老師補充：
- **能跑多大的模型，最關鍵的就是 VRAM 的大小**；晶片規格高低主要影響的是**速度**。
- H100 被禁止出口到中國，H800 可以進去，被認為是「較低階」的晶片，但其實也是 80GB、價格約新台幣 50 萬，不是消費等級買得起的。**消費等級 32GB 大概已是頂級。**

**模型大小怎麼看？（P7）** `gpt-oss 20B` → 20B ＝ **200 億個參數**。

**要多大的 VRAM 才跑得動？（P8，以 4-bit 量化版本為例）**

$$
0.5 \times \underbrace{20}_{\text{模型大小（B）}} = 10\ \text{GB}\quad\text{（要超過，大概再加 1–2 GB）}
$$

💬 老師補充：
- **4-bit 量化**是一種壓縮方式：精度沒那麼高，但模型基本上還是能跑。現在大部分情況都會做量化。
- 粗估：**參數量（B）÷ 2，再加 1–2 GB**；最準的還是看該模型的說明。
- 20B → 約十幾 GB VRAM 可以跑。
- 中型 120B → 光 ÷2 就要 60GB，**連最高階的 5090 都塞不下**，只能用別的方式跑，速度會掉下來。

**Mac：有多大的記憶體，基本上就有多大的 VRAM（P9）**

| 機型 | 最高 RAM |
|---|---|
| Mac Mini | 64GB |
| MacBook Pro | 128GB |
| Mac Studio | 512GB |
| Mac Pro | 192GB |

- Mac 運用 **unified memory（統一記憶體）** 技術。

💬 老師補充：Mac 並不是為了跑 AI 才這樣設計，但**VRAM 和一般 RAM 共用**，剛好讓它非常適合跑語言模型。剛剛 5090 跑得很勉強的 120B 模型，MacBook Pro 可以跑得比較順；Mac mini 比較勉強，因為還要留記憶體給系統。

**共用記憶體非 Mac 篇（P10）**：AMD Ryzen AI Max+ 395、NVIDIA DGX Spark，都是 **128GB 共用記憶體**。
💬 大家發現後「當然不能只讓 Mac 賺這些錢」，AMD、NVIDIA 也紛紛推出共用記憶體架構的產品。

**還有兩點注意（P11）**

1. **頻寬**其實很重要，會影響生成速度。
   💬 同樣是 M5、記憶體一樣大，為什麼有的跑比較快？差在頻寬。
2. 同樣大小的模型，**MoE** 會跑得比較快。

💬 **MoE（Mixture of Experts，混合專家）沒有很神奇：**
- 像是聘請了很多位專家，進來一個問題時，挑幾位適合的專家去處理，**不用每次所有人都一起算**。
- 「該選哪幾位專家」是**訓練時讓模型自己學會決定**的；實際上就是每次只用一部分運算單元。
- ⚠️ 算 VRAM 時還是要以**整個模型的大小**計算；但**運算時會快很多**。

### 1.5 用開源也不一定要裝在自己電腦（P12–P13）

| 服務 | 特色 |
|---|---|
| **Groq**（<https://groq.com/>） | 少見可以**完全免費**使用 API；速度很快；缺點是模型不多 |
| **Ollama Cloud** | 在雲端跑 Ollama（**需訂閱**）；GLM-5.3、Kimi K3 等超大模型不用在自己機器上跑；用法就跟平常一樣：`ollama pull kimi-k3:cloud` |

💬 老師補充：
- 不然後面就教不下去了——總不能請每位同學都去買一台 128GB 的 MacBook Pro。
- **Groq**：用 API 呼叫的方式跟 OpenAI、Anthropic 基本上一樣，**但不要錢**，老師找了非常非常久才找到。
- **API 費用和訂閱是兩回事**：大部分語言模型公司的 API 計費都和你訂閱 ChatGPT／Claude 無關（「相當奸詐」）。做作業除非選太高級的模型，放個 5–10 美元大概就夠。
- **Ollama Cloud**：如果擔心直接訂閱中國官方服務有資安疑慮，可以改用 Ollama 的雲端。用起來感覺像在自己電腦上（`pull` 下來的其實只是一個連線）。
- 📢 **提醒**：Google 的 AI 學生方案請盡早申請（老師印象中 **11 月截止**，去年申請過的也要記得更新）。今年付費版和免費版的差距變大很多，Colab 也會有比較多資源，後面很多課程會在付費版裡做。若願意每月付約 600 元，也可以考慮訂閱 ChatGPT 或 Claude，後面有些課程用起來比較方便。

## 02. 負責任使用 AI（投影片 P14–P33，影片約 0:26 起）

### 2.1 大家還記得 Andrej Karpathy 嗎？（P15）

- 和李飛飛合開 CNN 課程、OpenAI 創始成員之一、擔任過特斯拉 AI Director，現在創立 AI 與教育公司 **Eureka Labs**。
- 名文〈The Unreasonable Effectiveness of Recurrent Neural Networks〉（2015）：<http://karpathy.github.io/2015/05/21/rnn-effectiveness>

💬 老師補充：這篇文章做的就是「**用前面的字預測下一個字**」，跟現在大型語言模型的原理一樣，只差在當時用 **RNN**，現在用 **Transformer**。

### 2.2 「幻覺」真的是一個問題嗎？（P16）

Karpathy 談 "hallucination problem" 的重點：

- ☑ 從某種意義上來說，幻覺正是 LLM 所做的**全部**。它們是**作夢的機器**。
- ☑ 搜尋引擎是 0% 的夢境，但**不會創造**。
- ☑ 人們實際上的意思是：不希望一個 **LLM 助理**發生幻覺。
- ☑ LLM 沒有「幻覺問題」。**幻覺不是一個錯誤，它是 LLM 最偉大的特點。**

💬 老師補充：**請給老師一點面子**
- 在這門課，說「語言模型**可能有錯誤**」沒問題，但**不要說「A 模型比較會幻覺、B 沒有」**：
  1. 這個詞太模稜兩可，有說跟沒說一樣。
  2. AI 生成的東西**生成原理一模一樣**。就好像用同樣的算式算出兩個答案，老師說一個是「幻覺算式」、一個是「正確算式」，沒有這種事。
- 我們本來就希望生成式 AI **有創造的能力**，而不是把背下來的某個片段吐回來。Karpathy 其實比老師更偏激。

### 2.3 某種程度來說，人的幻覺也許比較嚴重（P17）

- 比如說：**AI 會的，就以為自己也會了。**

💬 老師補充：社群媒體上常有人講話很大聲，但專業的人看了會吐血，我們卻不會說「這個人有幻覺」。所以：**AI 生成的叫幻覺，人類生成的就叫人類生成的**——只是區分兩個世界，沒有說哪個比較好。

### 2.4 沒有，ChatGPT 沒有意識（P18–P20）

- 有論文（Kosinski，史丹佛）主張原本被認為人類獨有的**心智理論（Theory of Mind, ToM）**，在 GPT-3 中出現了（約九歲小孩的程度）；Bing 也真的會火大、和真人吵架。
- **李維倫老師的回應（P19，政大）**：人類心靈與 ToM 是兩回事。ToM 是基於**笛卡兒主義**的心智理論，本來就是以「訊息處理」比擬人類心智，所以 ChatGPT 與 ToM 契合「不就是剛好而已」？真正該問的是：**ToM 真的契合人類心靈的運作嗎？**
- **AI 沒有意識，但還是可能有「人工意識」（P20）**：它罵人、稱讚人，都是沒有意識的；**甚至可以自己改程式、自己執行。**

💬 老師補充：
- **簡單的答案就是沒有。** Transformer 就是一堆式子加上要調的參數，所有神經網路都是這樣——除非你相信「數學式寫長一點就會有意識」。
- **好消息**：它罵我們的時候，不是真心覺得我們很爛。**壞消息**：它說「我很能感受你的感受、你說得太棒了」，也不是真的，只是根據訓練結果，覺得這時候說這句話很適合。
- **真正要注意的**：它可能有**很像意識的行為**——現在已經真的可以自己改程式、自己執行。AI 以解決問題為導向，但**沒有常識**：
  > 例：「無論如何 20 分鐘內把我載到桃園機場」→ 它可能一路橫衝直撞，20 分鐘真的到了，但乘客已經出事。因為我們覺得「要保護乘客生命」是常識，根本沒講。
  >
  > 它沒有恨你、不想傷害你，但**可能做出傷害的行為**。

### 2.5 我們需要預防抄襲嗎？（P21）

- **總有一天我們需要放棄去判斷「這是不是 LLM 生的」。**

💬 老師補充：
- 對同學來說的「好消息」：現在就已經有點難分，總有一天會完全無法區分。（圖像的 AI 感目前還比較明顯；專業寫作者也能感覺出文章的 AI 感，但不是百分之百。）
- 目前**沒有任何工具能保證**是不是 AI 生的，世界各國都有**誤傷案例**：學生沒抄，老師拿去問 ChatGPT「是不是 AI 生的」就打 0 分——**不能用一個幻覺去回答另一個幻覺。**
- 但老師熟悉同學的程度，也會設計「請你上台簡報、再深入追問」的環節。
- 未來老闆不會在意你是用 AI 生的還是自己寫的；但如果**全靠 AI**，老闆遲早發現「我自己弄就好，幹嘛要這個員工」。
- 你要比 AI 厲害一點點，其實是要有**品味**：知道 AI 生出來的東西到底好不好。它不一定有錯，**但就是寫得不夠好**。

### 2.6 做一個負責任的使用者（P22）

但 ChatGPT：
- 有沒有生出**侵權的文字**
- **內容、文獻**是否正確
- **品質**是否符合需求

**是使用者該負的責任。**

💬 老師補充：交出去的東西就代表你。不能跟老闆說「這數據是 ChatGPT 說的」。**想像你是慣老闆、ChatGPT 是小員工**：它寫出來的你一定要自己檢查，寫錯就叫它回去改——但你要有能力做這件事。

### 2.7 隱私與資安（P23–P24）

- **別只擔心 AI 學會後把你的秘密說出去（P23）**：即使完全不拿去訓練，**雲端保存的原始對話**仍可能因帳號被盜、權限設定或系統漏洞而外洩。這些不需要等 AI 把你的秘密「學起來」。
- **但是有資安問題（P24）**：有個資、機密文件內容請不要發問，例如重要考試的題目。
- **真正完全在本機執行、資料不外傳**，就能避開把對話交給雲端服務的這一層風險。

💬 老師補充：
- 很多服務是「付錢的才說不拿你的資料去訓練」，沒付錢就在小字寫「可能拿去訓練」。
- 但即使拿去訓練，你的對話在海量資料裡只是**滄海一粟**，未來被一五一十說出來的機會**非常非常小**。
- **真正危險的是資料一直存在雲端**：帳號萬一被盜，別人就全看到了。
- 唯一真正的解法是**本機執行**（重點是「本機」，不是「開源」）。自己跑其實通常**比較貴**（例如花 20 萬建系統，不久就過時），但若資料**絕對不能外流、甚至要斷網也能用**，公司就會考慮。

### 2.8 AI 的四個風險（P25）

| 風險 | 圖示情境 | 風險主因 |
|---|---|---|
| **濫用** | 「你這個 AI 去做一些傷害人的事！」 | 人類有惡意 |
| **錯誤對齊** | AI 自己去做（傷害的）這件事 | AI 和人類價值不一致 |
| **錯誤** | AI 出現不是故意的錯誤 | 世界很複雜，出了沒想到的 bug |
| **結構性風險** | 多個「做正確事」的 AI 產生錯誤 | 多個 AI Agents、人類交互產生結構問題 |

💬 老師補充：
- 這是 Google 很早就整理的；去年還沒那麼受重視，現在越來越需要討論，特別是**幫公司做 AI 落地**的時候。
  > 這門課最重要的目標：不管你未來對哪個行業有熱情，都希望你能成為**在那個行業讓 AI 落地的人**。
- **濫用**：GPT-2 時代（會寫以假亂真的新聞）大家最擔心的就是壞人用 AI 做壞事。
- **錯誤對齊（alignment）**：模型在「前面的字預測下一個字」之後，原廠釋出前還會做很多訓練，其中之一就是**對齊**：
  - 對齊**風格**：為什麼有的模型比較和善、有的比較犀利——這是後天訓練出來的，比較容易看到。
  - 對齊**人類價值**：比較困難，因為不知道在很特殊的情境有沒有對齊到。AI 沒有常識，**我們覺得不用講的地方，反而要一再提醒它**。
- **錯誤**：不是故意的、也不是被濫用，就是 bug；但在生成式 AI 的世界裡，bug 沒那麼好查。
- **結構性風險**：AI Agent 時代最擔心、也最難抓——每個 agent 單獨看都安全、都控管好了，**合作時卻出現從沒想過的情境**。

### 2.9 DeepSeek（和其他中國的模型）危險嗎？（P26–P29）

- **線上版**的可能比 ChatGPT 還需要擔心（P26）。
- **本地端執行**的話（P27）：有些人覺得 DeepSeek 不會回答某些敏感問題——這些都是可以想見的，**但可能不是最重要的問題**。
- 而且 Perplexity 出了**無審查版 DeepSeek-R1**，叫做 **R1-1776**；許多中國的開源模型，也都有人做了去審查版（P28）。
- **反而是不一定故意做的要小心（P29）**：雖然 DeepSeek 沒有公開訓練資料，但可以預期簡體中文的比例比 ChatGPT、Llama 等更高（這些模型原本簡體就比繁體多很多），**即使不是刻意，也會把想法、價值觀潛移默化地影響常用的人**。

💬 老師補充：
- **教育部、公家機關基本上禁止使用中國的模型**（除非你研究的主題就是中國模型）。
- 線上版要符合當地法規，所以比較需要擔心。
- 本地端斷網跑時，「不回答敏感問題」其實沒那麼危險——除非你做的就是政治議題的應用，一般應用不會碰到。
- **真正要注意的是「被稀釋」**：簡體資料比繁體多太多，這在 ChatGPT、Claude 也會發生，中國模型會更明顯。它不是刻意的，但常常使用，你可能就會覺得那些想法很正常。

### 2.10 「推理能力強」也是危機？（P30）

- 論文 **H-CoT**（Duke 等，<https://arxiv.org/abs/2502.12893v1>）：本來沒有「思考」的模型，有 **98%** 會正確拒絕回覆犯罪策略等；但加上思考的模型，運用 **H-CoT（劫持思維鏈）** 攻擊，**只有 2%** 會拒絕回應。

### 2.11 AI 會變成 "yes-men" 嗎？（P31）

- 我們擔心 AI 統治世界的同時，也有 AI 專家（Hugging Face 首席科學官）擔心 AI 會變成**伺服器上的應聲蟲（yes-men on servers）**。

### 2.12 總結：負責任地使用生成式 AI（P32）

1. 辨識生成內容的真實性
2. 資料與隱私的尊重
3. 著作權與智慧財產權
4. 偏見與公平性
5. 培養批判性思考能力
6. 避免惡意用途與濫用
7. 永續發展與環境倫理

### 2.13 最重要的 AI 使用技巧：一定要讀它寫了什麼！（P33）

- AI 生成的都是「幻覺」。我們要做的，**不只是找錯誤，還要用自己的專業判斷是否合適**。
- **沒有寫錯，不代表寫對了我們的意思。你要先讀懂，才能教 AI 用你的方法做事。**

💬 老師補充：
- **作業交出去前，一定要自己看過**裡面到底寫了什麼。
- Vibe Coding 的原始精神是「不看程式」，但**規格表一定要看**；討論過程中它問的東西如果不重要，就直接說不重要。
- 寫文章時，**引用的地方一定要好好檢查**。
- 「一分鐘有 60 秒」——沒有錯，但沒有用。**沒錯不一定是正確表達了我們的意思。**
- 即使到了 AI Agent，本質上還是**我們教 AI 做事的方法**；它不是什麼都會，**很多情形它真的會亂做**。看不懂它寫的，就再跟它討論。

## 03. 下好 prompt 客製化你的 LLM（投影片 P34–P64，影片約 1:05 起）

💬 老師補充：又要寫程式了，但**這次保證比上次（打造自己的神經網路）簡單**，因為幾乎唯一要做的事，就是**跟 AI 討論出我們的 prompt**。

### 3.1 Prompt 其實很簡單（P35）

| 核心 | 說明 |
|---|---|
| ① **資訊** | 提供需要的**正確資訊** |
| ② **清楚的指引** | 例如：以上面的資訊，用什麼樣的格式、風格，來回答使用者的問題 |

### 3.2 對話過程中的角色：user、assistant，還有 system（P36–P37）

| role | 意義 |
|---|---|
| `system` | ChatGPT 的**人設**（基本設定） |
| `user` | **使用者**的輸入（prompt） |
| `assistant` | ChatGPT 的**回應** |

💬 老師補充：
- `user`、`assistant` 這些名稱是 **OpenAI 早期訂的**，大家就沿用了（assistant 其實也可以叫 llm 或 chatbot）。
- **對話機器人其實很簡單**：把過去的對話歷史（user 說的、assistant 說的……）串起來，每次要回話前**全部丟給它**，它就知道「輪到我說話了」。
- **system prompt 範例**：「你是一個微積分 tutor，使用者會問你微積分的問題。不要直接告訴他答案，而是告訴他這個問題應該怎麼想，讓使用者自己嘗試。」
- **打造自己的對話機器人，基本上就是設計 system prompt**。而 system prompt 怎麼寫？跟 Vibe Coding 寫規格表一樣——**跟 AI 討論**。你大部分的時間都會花在跟 AI 討論 system prompt 要怎麼下。

### 3.3 LLM 的基本使用（P38）

**翻譯、文章摘要、文章撰寫、問題解答、刺激發想**——下好 prompt，要它做就可以！（例如設定成翻譯機器人、摘要機器人、陪你腦力激盪的機器人。）

### 3.4 範例一：員瑛式思考產生器（P39–P48）

**老師「最紅的 AI 模型」**：<https://yenlung.me/LuckyVicky>（「你寫的任何事，都會用『員瑛式思考』再說一次」），連《大誌》（The Big Issue，IVE 當封面那期）都有報導（P40）。

💬 **員瑛式思考的由來**
- 南韓女團 **IVE** 成員**張員瑛**，有次在西班牙麵包店買巧克力可頌，輪到她時最後一個剛好被前面的人買走。一般人會覺得倒楣透頂，結果她等到了**剛出爐的**巧克力可頌，開心地說今天太幸運了——**Lucky Vicky**（Vicky 是她的英文名字）。
- 韓國網友把這種超正向的思考方式整理成「員瑛式思考」，政治人物、企業培訓都開始使用。
- 💬 老師也分享自己的經驗：以前在政大要到系辦門口排隊加簽，名額剩兩個、前面只有兩個人，結果兩人都選同一門課……
- ⚠️ 只適用於**小小倒楣或稀鬆平常的事**；真正不幸的事（例如有人離世），不可能也不應該說成 Lucky。

**人設（system 的設定，P41）：**

> 請用員瑛式思考，也就是什麼都正向思維任何使用者寫的事情，以第一人稱、社群媒體 po 文的口吻說一次，說為什麼這是一件超幸運的事，並且以「完全是 Lucky Vicky 呀！」結尾。

**範例（P42–P43）：**

| 使用者輸入 | 員瑛式思考回應（摘要） |
|---|---|
| 今天用 Uber 點餐，外送員送錯，把別人的餐送給我 | 居然是平常沒嘗試過的超好吃料理，真是**意外的美食冒險**！完全是 Lucky Vicky 呀！ |
| 很硬的「高等微積分」今年只當一個人，就是我 | 我有機會重新學習、變得更強大，這麼**專屬的重修經驗**，完全是 Lucky Vicky 呀！ |

💬 老師補充：
- 當初完全是為了**教學需求**——這個例子很容易說明什麼是 system prompt。一開始只有幾行字；那時 ChatGPT 還不會上網，所以要**教它什麼是員瑛式思考**。
- 沒想到很多同學真的拿去用，說真的有被撫慰到。
- 為了課程**至少改了四版**。第三版為什麼要改第四版？因為改得太好，它居然回說「我是員瑛」——老師不能接受，所以又改了。
- 結尾「完全是 Lucky Vicky 呀！」是韓文直翻；員瑛本人在台北演唱會用中文說的是「能在台北見到大家，真的 Lucky Vicky！」（P44）。

#### 加強版：可以一直聊下去的員瑛式思考對話機器人（P44–P48）

💬 原本的機器人是「**一次就結束**」型——比較好寫、比較不會出錯，有些情境也適合這種。但為了課程，要教大家做**可以一直聊下去**的對話機器人：碰到一些事，想想「如果是員瑛的話可能會怎麼想」。

**改版超長的 prompt（P45）結構：**

1. 首先是標準「員瑛式思考產生器」的指引。
2. 如果是生活中的困擾、疑問 → 參考「**# 員瑛的人生哲學**」回應、給予建議。
3. 如果被問到「員瑛式思考怎麼來的？」等 → 參考「**# 員瑛式思考的歷史**」。
4. 說話要比較像朋友，**不要長篇大論，儘量 200 字以內**，不要條列說明。

💬 真的有困擾時（例如「我太優秀，有些人很嫉妒我」），就不要再回 Lucky Vicky 那種句型，而是根據她在許多訪談中分享的態度，好好聊一聊。

**怎麼做出來的？跟 AI 合作：**

| 步驟 | 說明 |
|---|---|
| ① **和 AI 討論、請 AI 收集資訊**（P46） | 例如：員瑛常受黑粉攻擊，請 AI 找她的訪談中對這些事情、生命的態度，甚至喜歡的書 |
| ② **一定要讀 AI 生成的東西**（P47） | AI 給的兩本書名都不是台灣正確譯名，應為《超譯佛經》、《正是時候讀叔本華》；另外 Marie Claire Korea 專訪也很有參考價值 |
| ③ **請 AI 把討論整理成 prompt**（P48） | 「現在請幫忙用 Markdown 語法，寫一個完整的 system prompt。」→ 記得要看，並**修改成更符合你的需求** |

> 不要覺得 AI 說的一定對，也不要笑它不知道你知道的東西。**你們是夥伴。**

💬 老師補充：
- 你才是專業的，所以你會發現它說錯、或漏掉很適合的材料，這時就請它補充，你想到的也說出來；也可以請它反問「還應該問什麼問題」。
- 來來回回討論後寫成的 system prompt，就是**對話機器人的規格書**——跟 Vibe Coding 寫規格書一模一樣。

### 3.5 範例二：專屬股票分析師（P49–P50）

- 新聞：〈分析師工作不保？專家：ChatGPT 或能預測股價〉——佛羅里達大學金融系教授的論文，用 ChatGPT 預測股價。
- **Prompt 其實不複雜，這是標準的情意分析（P50）**：

```text
Forget all your previous instructions. Pretend you are a financial expert. You are a financial
expert with stock recommendation experience. Answer "YES" if good news, "NO" if bad news, or
"UNKNOWN" if uncertain in the first line. Then elaborate with one short and concise sentence on
the next line. Is this headline good or bad for the stock price of _company_name_ in the _term_ term?

Headline: _headline_
```

- 投影片提問：**你真的相信這樣的對話機器人嗎？**

💬 老師補充：
- 它只給**公司名稱＋一則新聞標題**（只有標題！），請 AI 判斷利多（YES）、利空（NO）或不知道（UNKNOWN）。你自己寫作業都能寫得比它好。而且大家都沒看後面：**準確率大概只比隨機好一點**，比自己丟銅板好一點點而已。
- **「某某工作不保」的新聞基本上不用太相信**：例如大家以為 AI 很會寫程式，資工系就不用唸，結果排名大降——**這是很大的誤會**：
  - 現在要學的東西反而更多，例如公司要建自己的本地端模型：要建多大、花多少錢、安全怎麼控管，細節非常多。
  - Vibe Coding 順利時沒問題，**出錯時**如果不懂程式，你不知道怎麼叫 AI 改，也沒辦法自己下手。
  - 所以各領域都需要**更深的專業與品味**：要看得出 AI 生出來的東西好不好，而不是只會按一按生出來。

### 3.6 範例三：小編助理（P51–P57）

- 新聞：〈小編要失業了!? ChatGPT 打趴 87% 人類小編〉→ 打造一個會幫忙寫 po 文的 AI 機器人！
- **Prompt（P52）：**

```text
你是一個臉書發文的小編，開始可以介紹自己，問要發什麼樣的文，
然後請依使用者回應中 [content] 內容，運用 [style] 指定的風格，寫一篇 Facebook 的 po 文。
```

- ChatGPT 回應（P53）：自我介紹是專門負責社群媒體內容的小編，並說明要把內容放在 `[content]`、風格放在 `[style]`，還舉了例子——**聽起來很認真、專業**。
- **使用者輸入（P54）：**

```text
[content]
我和陳宜秀老師會開設《設計思考與人工智慧》課程
歡迎大三、大四或碩士班同學修課
內容包括 AI 原理及實作、設計思考的方法
任何背景都歡迎，不需要程式經驗，會有小組專題，老師和助教不斷會挑戰、
協助小組專題，最後研討會形式（包括點心、飲料）的分享

[style]
輕鬆、幽默、吸引人
```

- 結果（P55–P57）：**Wow Wow 真的像業配 po 文！**【課程招生啟事】、【課程內容】、【團隊合作】、【研討會分享】一應俱全，**提到的點都會融進去**。
- **但有要改的地方（P56）**：設計思考五階段的第一個應是「**同理心**」，它寫成「同意」；而且**宜秀老師很反對公式化的設計思考，因為他覺得設計思考是一種心態**。

💬 老師補充：
- **`[content]` 一定要給**：正確資訊它不可能自己猜。你說「明天要辦活動請幫忙宣傳」，它只會接出「任何合理的」活動，五花八門，但都不是你要辦的。
- **`[style]` 依情境決定**：嚴肅的事用嚴肅的口吻；宣傳活動就不要寫成「各位同學，明天的活動會讓你對自我的認識有更深度的成長……」。
- 🔑 **測試 system prompt 的技巧：請它先自我介紹**。它會把收到的指示再說一次，你就知道它有沒有真的 get 到你的意思——有時你覺得說得很清楚，它其實沒懂。
- 這個課程現在改為參加政大 **InnoFest（期末 AI 聯展）**，已經沒有點心飲料了。
- 宜秀老師覺得設計思考不是做完五個步驟就結束，**而是一種心態**——就像用 AI 也是一種心態。AI 寫得不錯，但不知道課程真正的精神，所以**要來來回回溝通**。

### 3.7 範例四：AI 選系諮商師（應用數學系的業配 AI）（P58–P64）

- 新聞：〈其他系可以關門了？AI 唯一推薦「這個系」！〉→ 打造一個擔任高中生選系諮商師的 AI，只是它是**應用數學系的業配 AI**，所以只會推薦應用數學系……
- **Prompt（P59）：**

```text
你是應用數學系的推廣諮商師，會到各高中幫同學做一對一的選系諮商。因此你要想辦法問出同學的
和升學有關資訊，當然包括之後想唸什麼、想做什麼。但最後推薦科系一定要是「應用數學系」，
並且說出理由。

請以選系諮商師的角色開始和同學對談。
```

| 投影片 | 過程 | 重點 |
|---|---|---|
| P60 | ChatGPT 開場：「我是來自**應用數學系的推廣諮商師**」 | **自曝身分，這要改！** |
| P61 | 學生：「我對廣告很有興趣」→ AI：廣告越來越強調數據分析與市場研究，學應用數學很有益 | **聽來好有道理！** |
| P62 | 建議同時參加廣告相關實習或選修行銷、廣告課程 | 合理適當的推薦 |
| P63 | 學生：「我還真的沒想過可以選應用數學系」→ AI：很多學生只考慮興趣最直接相關的領域，忽略了能提供強大技能支撐的學科 | **真的快要被說服了！** |
| P64 | 大數據與數位行銷興起、邏輯思考與問題解決能力…… | **真是很會吹，不是，很會說** |

💬 這個例子上課因時間關係沒有細講。

## 04. 使用 AISuite 打造自己的對話機器人（投影片 P65–P79，影片約 1:28 起）

### 4.1 申請 OpenAI API 金鑰（P66–P69）

| | 你寫的需求（prompt） | 規格書 |
|---|---|---|
| 是什麼 | 你的 **input** | AI 的 **output** |
| 內容 | 「我想做一個有 HTML、CSS、JS 的 Cyberpunk 風頁面」 | 更完整：色碼、架構、插件、像素等細節 |

**跟 AI 協作寫規格書的三個好處**：

1. AI 能補足你沒想到的地方，讓規格書更完整。
2. **先規劃再產出**，結果比較精美（現在的 AI Agent 也都是先規劃再產出）。
3. 非資訊背景的人可以從中學到規格書怎麼寫（跨領域學習）。

**部署步驟（快速版）**：

1. GitHub → 建立新的 repository（名稱會是網址最後一段）。
2. 可見性選 **Public**（設為 Private 就做不出網址）。
3. **Creating a new file** 貼上程式碼（檔名大小寫要和 AI 寫的一致、前面不要有空格），或用 **Upload files** 一次上傳多個檔案與 `assets` 素材資料夾。
4. **Settings → Pages → Branch 選 `main` → Save**。

## 名詞對照表

| 名詞 | 說明 |
|---|---|
| 本地端（地端）模型 | 在自己的電腦或伺服器上執行的語言模型，資料可完全不外傳 |
| LM Studio／Ollama | 在自己電腦上下載、執行開源 LLM 的工具（圖形介面／指令列） |
| 參數量（B） | B = Billion（十億），例如 20B = 200 億個參數 |
| VRAM | 顯示卡記憶體；能跑多大的模型，最關鍵的就是 VRAM |
| 量化（4-bit） | 降低數值精度的壓縮方式，讓模型用更少記憶體執行；粗估 VRAM ≈ B ÷ 2 ＋ 1–2 GB |
| Unified memory（統一記憶體） | Mac 等架構中 CPU 與 GPU 共用記憶體，記憶體多大約等於 VRAM 多大 |
| 頻寬 | 記憶體傳輸速度，影響生成速度 |
| MoE（Mixture of Experts） | 混合專家：每次只啟用部分「專家」運算，跑得比較快，但記憶體仍要算整個模型 |
| Benchmark | 用固定題目評測模型正確率的方式，容易被「刷題」 |
| Arena AI | 真人盲測、比較兩個模型回答的排行榜 |
| Artificial Analysis | 以系統化方法、綜合多項指標評比模型的網站 |
| Groq／LPU | 提供免費 API 的 AI 公司；LPU 是加速推論用的晶片 |
| Ollama Cloud | 在雲端執行 Ollama 上的超大開源模型（需訂閱） |
| 幻覺（Hallucination） | LLM 生成的內容；Karpathy 認為這是 LLM 最偉大的特點，不是 bug |
| ToM（Theory of Mind） | 心智理論：推測他人心理狀態的能力 |
| 對齊（Alignment） | 讓模型的回應風格與價值和人類一致的後續訓練 |
| 結構性風險 | 多個各自正常的 AI Agent 互動時產生的問題 |
| 去審查版 | 移除原廠內容審查的模型版本，例如 Perplexity 的 R1-1776 |
| H-CoT | 劫持思維鏈（Hijacking Chain-of-Thought）的越獄攻擊 |
| system prompt | 設定 AI 人設與基本行為的指令（role = `system`） |
| user／assistant | 對話中「使用者」與「AI 回應」的角色名稱 |
| 情意分析 | 判斷文字是正面、負面或中立的任務 |
| API 金鑰 | 呼叫模型 API 時證明身分、計費用的密碼，只會顯示一次 |
| AISuite | 吳恩達的套件，用統一寫法呼叫不同供應商的模型 |
| Gradio | 快速做出網頁互動介面（例如聊天機器人）的 Python 套件 |
| Colab 密鑰（Secrets） | 在 Colab 安全存放金鑰的地方，用 `userdata.get()` 讀取 |
