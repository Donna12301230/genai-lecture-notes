## 01. 學做大老闆：現代的 Agentic AI

### 1.1 回憶我們 AI Agents 的定義（P3）

- 在 LLM 時代，AI Agent 基本上就是**教 AI 用「我們做事的方法」做事情**。
- **AI Agent = AI Model + Harness**

💬 老師補充：
- 再強調一次：是**我們**做事的方法，不是別人做事的方法。上完這門課，希望大家不要再到處找「有沒有人寫好的 skill 給我用」「有沒有人的 prompt 給我抄」——別人的專業、做法、想做的事都不一定跟你一樣，即使同樣專業，做法也可能不同。
- 這是比較能讓大家理解的**操作型定義**。
- AI Model：任何一個大型語言模型；Harness：教 AI 怎麼做事、怎麼檢查它做出來的結果。

### 1.2 最後我們要出去吹牛的那張圖（P4）

| 範圍 | 名詞 |
|---|---|
| Chat Bot | Prompt Engineering、Context Engineering |
| AI Agent | Harness Engineering、Loop Engineering、Graph Engineering |

- 我們會學到 AI Agent 其實只是「**教 AI 做事的方法**」。

💬 老師補充：
- 這張圖已經出現第三次，現在**正式進入 Harness Engineering**。
- Loop Engineering、Graph Engineering 都算是 Harness Engineering 的一種（特別是 Claude 那一系的分類方式）。不一定要完全照這個思維，但外面的人會講到這些字，要知道在講什麼，不然會被恥笑。

### 1.3 上次我們學習用程式寫 AI Agent（P5–P6）

- 上次用 **AISuite** 自己手刻 AI Agents：**Reflection、Tool Use、Planning**。
- 但這多少還是有點麻煩——**完全沒有自己是老闆的感覺**。

💬 老師補充：
- 上週刻意每次只用一種技巧（實務上通常是混用），目的是讓大家理解 AI Agent 是什麼。Tool Use 也只用了一個「自己寫的假工具」；真實世界可能有系統提供資訊，讓生成式 AI 把該有的資訊叫出來。
- 上週已經感受到 AI 能幫你查資料、按計算機、來回修改文章、先打草稿……但**還要寫程式**。身為大老闆，有時候就是想「出一張嘴」：我覺得應該這樣做，人家就去照辦。
- 這週的目標：**做一樣的事，但不要寫程式，而且叫它做更多事**。
- 外面說 AI Agent「出一張嘴就幫你完成任務，什麼都不用做」——今天會發現**還是要做一些事**，但跟你想像的不一樣，至少沒有寫程式這麼辛苦。

### 1.4 例子：我的桌面好亂（P7–P8）

**以前（純 LLM）的對話**：

> 你：我的桌面好亂，可以幫我整理嗎？
> LLM：好的！請把桌面上所有檔案的名稱、包括副檔名都貼給我。
> 你：（打了 87 個檔名……）
> LLM：建議分成 5 類：作業、照片、講義、安裝檔、其他。以下是每個檔案該放的資料夾……

**AI 出一張嘴，事情都你在做！**（P8）

1. 你：一個一個抄檔名給 AI。
2. AI：想分類、排清單。
3. 你：自己建 5 個資料夾。
4. 你：87 個檔案一個一個拖進去。

> AI：「沒辦法，我沒手啊！」

💬 老師補充：
- 純 LLM 只會做文字接龍。你當然可以聰明一點，請它寫程式把檔名列出來，但不管怎樣，**辛苦的部分都是你做的**。
- 感覺上 AI 比較像老闆，**你比較像打工仔**。

### 1.5 還記得 Tool Use 嗎？（P9–P10）

- 「給我讓我可以處理檔案的工具。」
- 於是**變成你出一張嘴，AI 來完成！**

1. 你：幫我整理桌面，**先給我看計畫**。
2. AI：自己打開資料夾、看所有檔案。
3. AI：提出分類計畫。
4. 你：可以，照做。
5. AI：建資料夾、搬檔案，回報結果。

> 你：「我是慣老闆。」　AI：「事情都我做。」

💬 老師補充：
- AI 以前做不到，關鍵只是**它碰不到你的電腦、不能處理檔案**。照上週 Tool Use 的概念，它只要「出一張嘴」說要建哪個資料夾、把哪個檔案搬到哪，再找一個工具（小程式）去執行就好。
- 「**先給我看計畫**」很重要。也可以叫它直接開始做，但做出來可能讓你「大驚奇」。
- 因為語言模型每次的做法都有一點點不一樣：你上次覺得整理得不錯，下次在朋友面前得意地表演，可能就沒那麼好了。
- 做完你去看一下，「不用跟它講做得很好」——雖然只是很簡單的事，但開始有**當老闆的感覺**了。

### 1.6 從「問 AI」到「交辦給 AI」（P11）

| | 對話式 Chat | 代理式 Agentic |
|---|---|---|
| 你在做的事 | 問問題 | 交辦一件工作 |
| AI 像是 | 顧問 | 員工、同事 |
| 過程 | 一問一答，你全程在場 | 多步驟自己做，你可以離開 |
| 能碰的東西 | 對話框裡的文字 | 檔案、瀏覽器、工具 |
| 你拿到的 | 一段回答 | 一份成品 |

💬 老師補充：
- 以前的 Chat AI 說是顧問，老師覺得**更像老闆**，因為只出一張嘴；現在真的變成你的員工或同事，「而且感覺比較低你一級」。
- 交辦的工作可能需要搜尋，例如幫你查想買的東西哪裡最便宜。
- 多步驟它自己做（就算要開瀏覽器也可以），你可以去泡咖啡、喝咖啡，回來再看它做得怎麼樣（雖然現在都會想很久）。
- 以前拿到的只是一段回答，不一定是你真正要的成品；現在可以讓它生成一份、甚至**很多份**報告。

## 02. Agentic AI 工作流

### 2.1 LLM 本身，只會生成文字（P13）

- 我不會打開你的資料夾。
- 我不會建資料夾、修改檔案。
- 它不能自己上網查最新資料。
- 那 AI 是怎麼會「**動手**」的？

💬 老師補充：
- 「不會打開你的資料夾」這件事真的差很多：如果有 200 個檔案要請 AI 看，以前得一個一個上傳，會發瘋。
- 以 **LLM Wiki** 為例（之前介紹過、今天要實作）：讀一個原始檔，可能要生成好幾個 wiki 檔（一個小觀念一個 wiki），中間還有互相連結；要修改時，可能有幾個要改、有幾個要新增。純 LLM 也做得到，但它會告訴你「第一個檔案的新版長這樣、第二個長這樣……」，**你得一個一個自己存**——就是打工仔的感覺。
- 能存取檔案系統、建資料夾、改檔案，「看起來好像很小，但其實很大」。

### 2.2 記得我們課程核心公式（P14）

**AI Agent ＝ AI Model ＋ Harness**

| 元件 | 角色 | 負責 |
|---|---|---|
| AI Model | 大腦 | 負責**想**：理解、規劃、判斷、生成 |
| Harness | 工作裝備 | 負責**做**：把模型說的「我要開這個檔案」真的執行，再把結果回報給模型 |

- **AI Agent 就是：教 AI 用你的方法做事。**（💬 兩者缺一不可）

### 2.3 上個單元我們就做過 harness 了！（P15）

| 之前用 AISuite 寫的 | Agentic AI 使用方法 |
|---|---|
| 問問題 | 問問題 |
| 自己寫的 Python 函數當工具 | 讀寫檔、終端機、搜尋 |
| 寫在程式裡的 system prompt | `CLAUDE.md` ／ `AGENTS.md` |
| 自己處理錯誤和重試 | 產品幫你處理 |

💬 老師補充：
- 未來還是有很多機會要**寫程式做 AI Agent**（例如開發公司內部的一個小系統），不要以為就不用寫程式了；但現在有很多工具讓寫程式的部分可以很少。**今天則是完全只出一張嘴。**
- 讀寫檔、呼叫終端機、搜尋這些工具，上週用 Python 其實都寫得出來，搞不好有同學已經做出來了。
- 以前打造對話機器人，最重要的是下 **system prompt**。在專案型的 AI Agent 裡，我們沒有要改語言模型本身（它是 Claude 就是 Claude、是 ChatGPT 就是 ChatGPT），所以 system prompt 改用一個**設定檔**來下：**`CLAUDE.md` 就是以前的 system prompt**，這樣想就好。
- 看別人的 Claude Code 教學會覺得好複雜：要設 CLAUDE.md、還有各種指令……其實都可以出一張嘴。
- CLAUDE.md 曾被詬病「明顯只屬於 Claude」（但 Claude 比較早做，也不能說它錯）；模型這麼多，所以大部分地方通用的叫 **`AGENTS.md`**。
- 檔名其實不一定要固定，就像 `import numpy as np` 的 `np` 只是習慣用法；但有些模型會**自動去找** AGENTS.md 先讀，地位跟 CLAUDE.md 一樣。

### 2.4 一個完整的 harness 有什麼？（P16）

| 元件 | 說明 |
|---|---|
| 💻 工作環境 | 有自己的電腦（沙盒），可以存檔、跑程式 |
| 🧰 工具 | 讀寫檔案、終端機、瀏覽器、網路搜尋 |
| 🔌 連接器（MCP） | 接上 Gmail、行事曆、雲端硬碟等你的 App |
| 📘 技能（Skills） | 一個資料夾＋一份 `SKILL.md`，教它某件事的「**標準作業流程**」 |
| 📜 規則檔 | `CLAUDE.md`／`AGENTS.md`，每次上工前先讀 |
| ⏰ 排程 | 時間到了，自己開工 |

💬 老師補充：
- 看起來很複雜，其實「根本不用管它」——**懂原理，很多東西出現都是很自然的事**。上面三個（工作環境、工具、連接器）基本上就是上次說的 Tool Use，方法有一點點不一樣而已。
- **工作環境**：有些語言模型有自己的電腦（ChatGPT、Claude 都有）；Grok 基本上只能用它在雲端上自己的電腦，不能用你的電腦；有些是混用。
- **連接器**其實又是工具，只是別人（OpenAI、Anthropic）寫好的，可以連上 Gmail、行事曆、雲端硬碟，也可以連上 LINE。
  - 老師的例子：以前 LINE 他，99% 的機會不會看見；現在特別做了一個 agent，提醒他「有人問了看起來是你要回的」。廣告、某公司說送你 coupon 這種就不用提醒。
- **規則檔**就是新來的可愛 AI 員工的**員工手冊**（＝system prompt），叫什麼名字都可以，等一下會說。Claude 每次把資料夾弄進來都會自己讀 CLAUDE.md；很多 AI 會自動讀 AGENTS.md；不會的，叫它去讀就好。
- **排程**：專案設計好後，排定時間讓它自己做。例：每天早上八點上網搜尋 AI 新聞，選幾條比較重要的做成網頁——**你自己的 AI 日報**。告訴它你對哪一類比較有興趣，它會慢慢調整成最適合你的日報（今天的作業也可以做這個）。
- **Skills** 等一下自然出現時再介紹（見 💬 5.5）。

### 2.5 模型大家都差不多，決定好不好用的是 Harness（P17）

> 「給我讓我可以處理檔案的工具。」——不論 Claude（`CLAUDE.md`）或一般（`AGENTS.md`）

💬 老師補充：
- 不用一直在意「我用的模型是不是世界第一」，遲早另一個也會趕上來。Claude 稍微穩一點點，但 ChatGPT、Gemini、Grok、Meta 幾乎每一家都經歷過「被評比很差、跟人家不能比」的時期。
- 懂原理就知道：都是「前面一堆字，接下一個字」，能搜刮的資料基本上都搜刮來了。**最頂級的大型模型水準差不多**，差別在**它的 Harness 怎麼設計**——好消息是：**你可以自己設計你的 AI Agent**，這也是這門課的重點。
- 但要注意：**比較小的模型跟最頂級的還是有一段差距**。小模型還是有用處，例如想在自己電腦上跑、做不太複雜的事。

### 2.6 好老闆「通常」要說清楚三件事（P18）

| 要說清楚的事 | 問自己 |
|---|---|
| 要什麼成品 | 做完我會拿到什麼？放在哪？什麼格式？ |
| 怎麼算做完 | 我要怎麼驗收？ |
| 有什麼限制 | 哪些可以動、哪些不能動？ |

> 重點就是，**不要讓我猜測！**

💬 老師補充：我們要當**好老闆**，不是慣老闆——好吧，還是慣老闆，但要跟員工**說清楚**要它做什麼，它才能徹底執行到我們希望看到的東西。讓可愛的 AI 天馬行空，有時你會覺得很有創意，但大部分時候它會想得跟你不一樣。

### 2.7 同一件事好的／壞的交辦方式（P19）

| 爛的交辦 | 好的交辦 |
|---|---|
| 幫我整理桌面。 | 幫我整理「桌面」這個資料夾。依用途分類，資料夾名稱用中文。不要刪除任何檔案，看不出用途的放進「待確認」。動手前先給我看分類計畫，做完列出每個檔案搬到哪裡。 |

💬 老師補充：
- 爛的交辦它其實也會整理，「整理得通常也還可以」，大家回去夠勇敢的話不妨試試。缺點是空間太大：這次整理成這樣，下次又整理成另一個樣子。
- 好的交辦就是**說得越詳細越好**。「分類計畫先給我看」——這就是大老闆的感覺；「做完列出每個檔案搬到哪裡」——通常我們也不會看，但我們叫它要做（這就是大老闆開心的地方）。

### 2.8 可以做「專案型」AI Agent 的工具（P20）

| 工具 | 模式／特色 |
|---|---|
| ChatGPT | Work ／ Codex |
| Claude | Chat 整合（原 Cowork）／ Code |
| Gemini | （本次示範使用） |
| OpenWorker | 開源，並且可用開源模型 |
| GrokBot | 純雲端 |
| Muse | Meta AI |

💬 老師補充：
- 比較不幸的是：**幾乎都要付費版**。
- **ChatGPT**：標準模式在 **Work** 裡；**Codex** 是程式的專案用的。
- **Claude**：本來叫 **Cowork**，現在 Cowork 跟 Chat 已經合併，不用再特別切換模式。
  - 最早大家是用 **Claude Code** 做這類事——後來發現 Claude Code 不只能寫程式，大家說它名字取錯了；現在它又越來越偏向寫程式專案（例如 push 到 GitHub、下指令），大家又覺得名字取對了。
  - 很多今天介紹的做法（寫 CLAUDE.md 告訴 AI 要做什麼、有什麼限制、什麼時候自己看著辦、什麼時候該問我）都源自 Claude Code。
  - **今天的作業不需要 Claude Code**，用 Cowork 或 ChatGPT Work 這種「親切版」就好，也比較自然。
- **Gemini**：今天用它示範，因為 Google 又開放**學生身分可免費使用一年付費版**。（⚠️ 桌面版存取檔案的限制見文末結語）
- **OpenWorker**：學期初本來想讓大家用它。完全開源（老師提到是「恩達老師」寫的），就像 ChatGPT Work、Claude Cowork 那種工具。
  - 最大好處：可以用**所有開源模型**，例如在自己電腦用 **Ollama** 跑你能跑的最大模型。
  - 缺點：本地端小模型跟第一梯隊的模型還是有差距，做 AI Agent 時會明顯感受到。Ollama 的 Cloud 版能在雲端跑大模型、表現接近第一梯隊，但也要付費。
  - 若作業成果跟老師示範有差距，可以說明「我用的是 OpenWorker、比較小的模型」。
  - 有些機構使用 agent 時需要**完全斷線、全部放在自己的地端**才百分之百安心；有這種經驗的人才很受歡迎。
- **GrokBot**：純雲端，一定要用它自己的雲端硬碟開專案，不能在自己電腦上開。Grok 曾被說「真的不行」，GrokBot 最近又很紅——再次說明**不用太在意哪個模型今天最好**，評測也不一定可信。
- **Muse**：Meta AI 的，想走 Claude Code 這種模式；**台灣還沒開放**，是老師唯一沒試過的。

### 2.9 AI Agents 專案通常會設一個專案資料夾（P21）

- 在自己的電腦上開一個**專案資料夾**，讓你的 AI 有**存取權限**。

💬 老師補充：名字隨你取，專案相關的檔案全部放在裡面；AI 能碰到的就是這個資料夾裡的東西。有些工具連上去就會問要不要給存取權限——「廢話，不然我告訴你幹嘛」。（GrokBot 例外，要開在它的雲端）

### 2.10 寫一本員工手冊（P22）

| 檔名 | 用途 |
|---|---|
| `CLAUDE.md` | Claude 專用 |
| `AGENTS.md` | 一般通用 |

- 老話一句：**這種規格書會由我們和 AI 討論出來！**
- 不一定非要這樣叫不可，也可以跟 AI 說先讀指定的「員工手冊」。

💬 老師補充：
- 別人寫的 CLAUDE.md／AGENTS.md 看起來都很複雜。**不要把別人的整個拿來直接用**（像拿別人寫好的應用程式那樣），通常不太好用，因為別人的想法跟你不一樣。可以說「參考這一個，但我要改什麼」；就跟下 prompt 一樣，一定會有自己的調整。
- 找別人的 **skill** 通常也不是最好的方法，**除非那個 skill 真的很複雜**（例如寫網頁、做 PowerPoint 的 skill），很難靠出一張嘴讓 AI 學起來，才考慮用別人弄好的。
- 推薦做法跟以前一樣：**跟 AI 討論，最後說「根據我們的討論把規格書寫出來」**。也可以叫 AI 問你：「我現在想做這樣的事，有不清楚的地方你可以問我」——完全大老闆的口吻。它會問得很仔細（之前 Vibe Coding 時應該體會過），你再一一回答。

### 2.11 對話越來越長怎麼辦？每次先讀員工手冊（P23–P24）

- 當然可以一直在**同一個對話**中進行這個專案（不寫 AGENTS.md，一步一步教它），只是：
  - 對話會越來越長……
  - 換一台電腦就讀不到……
- 每次開對話框就先要求讀「員工手冊」：「**請先讀 AGENTS.md，瞭解這個專案的內容。**」
- **不用擔心沒有寫完美，可以持續改寫。**

💬 老師補充：
- 討論完，它會寫一個建議的 CLAUDE.md，你說「看起來不錯」就好。還沒想清楚的以後再想——你是慣老闆，隨時想到就跟它講，「還可以罵兩句：你怎麼自己沒有想到」。AGENTS.md **不是永遠不動的東西**。
- Claude 說得很清楚：專案資料夾進來，它一定會自己讀 CLAUDE.md；但不是所有模型都會，**最保險的方法是每次開新對話框就叫它先讀一次**，多讀幾次沒關係。

## 03. 一些專案範例

### 3.1 「呆一布講義」工作資料夾（P26–P27）

- P26：實際的工作資料夾裡有 `_to_delete`、`assets`、`CLAUDE.md`、`ideas`、`index.html`、`lessons`、`ppt`、`log.md`、`README.md`、`shared-assets`、`slide-notes`、`ppt-final`、`SETUP.md`……「**這看來好複雜**」
- P27：**其實沒有很複雜**：

```text
CLAUDE.md          員工手冊
ideas/             整理想法
  → slide_notes/   投影片筆記
    → presentation/  最終的簡報
assets/            我們的小插圖
index.html         首頁
```

💬 老師補充：
- 目的：例如「我今天想教大家 Ollama 怎麼用」，請它**自動生成教學投影片**，並放進我們自己的貼圖。
- 流程：
  1. 請 AI 先上網研究：Ollama 教學應該教到什麼程度。想得夠清楚就講清楚（例如只教到哪裡、太細的不用教、但 Ollama Cloud 怎麼用要教）。
  2. AI 收集資料、做好筆記，放進 `ideas`。
  3. 整理成 `slide_notes`。
  4. 做成簡報。**最容易成功的方法是寫成 HTML**——跟上次 Vibe Coding 一樣，只是現在是「做簡報的 Vibe Coding」。
- 其他看起來複雜的資料夾，大部分是 AI 在做的過程中**自己覺得應該加的**，不是我們說的。這也是為什麼老師一直說：**不要在 GitHub 上找別人的專案 clone 下來直接用**，第一次看一定覺得超級複雜。
- 例外是小插圖：如果一定要用**自己風格的素材**，就要自己準備並告訴它，不然每次都讓它自己生太累，也不一定符合你的標準。

### 3.2 做出來的結果（今天的作業）（P28）

- 網址：<https://diveai-lab.github.io/diveai-lessons/>
- 「一起跳進 AI，當它的呆萌好夥伴」講義庫：每一份都可以直接在瀏覽器打開、翻頁閱讀。

💬 老師補充：
- 首頁 `index.html` 列出每份講義，例如 AI 入門作業的五個問題：為什麼 AI 只是一個呆萌型 AI 機器人？打造自己的呆一布要學哪一個函數？為什麼說 LLM 生成的都是幻覺？……點進去就是 AI 做出來的網頁。

### 3.3 呆一布粉專貼文工作室（P29–P30）

- P29：「這是我寫的哦。」（資料夾裡有 `AGENTS.md`、`index.md`、`log.md`、`assets`、`reference`、`visual`……）
- P30：每天出一篇貼文（例：〈Agent Skills：換了 AI，做事的方法不用重新教？〉）

💬 老師補充：
- 一開始：老師給一個 AI 主題 → AI 研究、寫成粉專 po 文 → 老師覺得「寫得也太生硬了」→ 改到滿意 → 想幾個標題 → 畫封面圖。

- 有趣的是：八點是老師隨便說的，它自己想到「八點要給你，我要先搜熱門主題、寫文章，不如七點半就開始，你覺得怎麼樣？」——「廢話，好，你就去做」。
- 目前**還沒很穩定**，所以不敢讓它全自動；很穩定時，就可以讓它每天自己寫、自己 po。
- 老師也說 P29 的資料夾有些不該放在根目錄的檔案放在根目錄，還要再教它。範例就在「呆一布 AI」粉專。

### 3.4 圖像風格轉換專案（P31）

💬 老師補充：老師原本的貼圖是左邊那種**鉛筆細線**的風格，但 AI 很不會學細細的手跟腳，常辨識錯誤；所以乾脆請它「改成你會畫的風格，但還是要盡量像」，就變成右邊（ChatGPT 畫的）。有一個專案專門生這種貼圖——但其實沒有說得這麼簡單，它常常生得不好，還要跟它討論怎麼辦。

## 04. Karpathy 的 LLM Wiki

### 4.1 簡單說，是打造你自己的 Wikipedia（P33）

```text
你找的資料 ──→ raw/ ──（教 AI 怎麼把檔案產生／修改 wiki 檔）──→ wiki/
                                                              └── index.md
```

💬 老師補充：
- 把找到的資料放進 `raw`，叫 AI 去讀。讀完後把內容切成**一小塊一小塊**適合的 wiki——不只是單純的文字切塊，還記錄這個 wiki 的**原始資料從哪裡來**、跟**其他哪些 wiki 有關聯**的連結。
- 學過 RAG 之後更清楚：Karpathy 本來的目標很可能是把這些小塊做成 RAG 系統（相關連結放在 metadata）；後來他發現**不用做 RAG 就很好用**，就打造成自己的知識庫系統。
- wiki 裡有一個 **`index.md`**，記錄所有 wiki 大概的內容。問問題時，請它看 index.md，找出哪幾篇跟今天的主題有關——它的找法**完全符合人的想像**。
- 跟 RAG 比較：embedding 出來的是人看不懂的抽象向量；這裡我們**完全知道它記了什麼**，找對找錯用人的判斷就能判斷——比較人性化，也就是**比較有可解釋性**。
- 資料量真的太大時可能還是需要 RAG；但切成一塊塊的基本工作已經做好，要再做成 RAG 也比較簡單。

### 4.2 Karpathy Gist 分享 LLM Wiki（P34）

- <https://bit.ly/llmwiki>（GitHub Gist：`karpathy/llm-wiki.md`——"A pattern for building personal knowledge bases using LLMs."）

💬 老師補充：
- 它**不是 CLAUDE.md**（Karpathy 是用 Claude Code 做的，但分享的不是規則檔），而是比較抽象的**想法**；他也很推薦大家分享時分享想法。
- 你跟 AI 來來回回討論出來的想法，整理起來對別人幫助也很大——別人看了可以說「這裡我要改成另一個用法」。
- 再強調一次：直接 clone 別人含 CLAUDE.md／AGENTS.md 的 GitHub 專案來執行，通常不太適合你；**參考後改寫成你的版本**是可以的。
- 很推薦仔細讀這份 Gist；英文讀得太辛苦，可以請 AI 翻成中文。

### 4.3 Farzapedia：個人化的 Wikipedia（P35）

- <https://bit.ly/farzawiki>：用這個方法做出來的個人 Wikipedia（由多年日記整理成的個人知識庫）。
- 💬 老師和助教都介紹過，這是第三次；今天會教大家怎麼做出這種東西，想照他的方法做，連結裡有他分享的做法。

## 💬 05. 課堂示範：用 Gemini 當老闆

### 5.1 示範一：請 AI 依規則整理桌面（影片約 1:23 起）

- 老師的桌面「也是這麼亂」。之前已建好一個「桌面整理」專案，裡面的規則檔不叫 AGENTS.md（應該是 ChatGPT 取的名字）——「其實可以叫 AGENTS.md，但它自己取的我們也不要改」。
- 步驟：選擇專案（連結到桌面資料夾）→「請讀一下〇〇，瞭解怎麼整理我的桌面」→「請依裡面的說明，再度整理我的桌面」。
- 權限：老師選了大家**比較不推薦**的「代我核准」，免得它做到一半還來問。
- 結果：桌面乾乾淨淨，只剩三個檔案和「AI 日報」資料夾（某個 AI 每天做的日報，後來叫它不要放桌面）。

### 5.2 示範二：用 Gemini 建立 LLM Wiki 專案（影片約 1:26 起）

1. 在自己的電腦上建一個**空的**專案資料夾——裡面的東西準備讓可愛的 AI 去建。
2. 打開 Gemini（桌面 App）→ 新對話 → 加入資料夾 → 允許存取（「廢話，不然它要怎麼做事」）。
3. 交辦（大意）：「我想做一個〇〇相關研究的 LLM Wiki，請參考 Karpathy wiki 的做法，寫**中文的** AGENTS.md，然後建立相關資料夾或檔案。」
   - 不說「全中文」，怕它連檔名也改成中文。
   - 💡 更好的做法：先請它把 AGENTS.md **寫給你看、不要直接存檔**；今天為了偷懶直接讓它寫。
4. 把 Karpathy Gist 的整段文字 copy 起來貼給它（「最愚蠢的做法」），它就開始執行。

💬 老師補充：
- 「我們做的最偉大的動作，就是把 Karpathy 的 LLM Wiki 指引貼上去，沒有其他事情了。」所以真的很好做——**陷阱就是你會覺得很好做**。
- 外面有人說「Karpathy 這個方法沒什麼功能」「我會再加什麼」——廢話，它又不是給你寫死的規則，**你希望有什麼變化就跟它講**。
- 過程中的小插曲：
  - `index.md` 被放在最外層——因為剛剛沒說清楚，所以每次做的都不一樣（上次做的就整整齊齊）。
  - 忘了放小貼圖，難怪它好像什麼都不會做——補上 `assets` 資料夾，並告訴它**只能用這些小貼圖**。
  - 除了 `assets` 是老師放的，**其他所有東西（包括 AGENTS.md）都是 AI 建的**。
- 加入第一篇文章時補一句：「**以後我貼給你的文章，都請保存到 raw 資料夾裡**，再建立或更新相關的 wiki.md 檔還有 index.md 等檔案。」——沒講的話，它會處理文章，但不會把原文放進 raw。

### 5.3 LLM Wiki 的應用：依知識庫寫筆記、做 HTML 簡報（影片約 1:41 起）

老師之前下的 prompt 大意：

- 想把 wiki 知識庫做擴充應用：我會問一個問題或做一個研究。
- 請**完全依照 wiki 裡有的內容**，寫成一份 `.md` 筆記，放到 `notes` 裡。
  - 為什麼？可能只靠 wiki 寫得沒那麼好，但這樣才能**確認 wiki 知識庫是完整的**。
- 可以上網搜尋相關主題，但**不在 wiki 裡的內容先不要用**；最後列出**建議參考文獻**，之後再把它們做成 wiki。
- 根據筆記做出簡報的主要內容，放在一個資料夾裡，最後做成 **HTML 簡報**。
- **先不要動任何東西**；你覺得還有什麼要考慮、要澄清的地方，可以問我。

💬 老師補充：
- 它會問很多問題，照理說應該**一一好好回答**（老師之前就是這樣做）。示範因為時間關係回「請依你的建議」，但補充強調：內容上只能用 wiki 裡有的；可以幫忙搜尋找相關資料；最後列出**可以點擊、可下載**的建議文獻，之後做 wiki 化流程。
- 接著討論**簡報風格**：配合 `assets` 小貼圖的可愛風格、日系文青、**低飽和度粉彩**配色、要支援 **LaTeX**，「請給我三個範例」。（「我相信念設計的同學會寫得比較好，老師已經盡力了。」）
- 試做一次：以「**什麼是專業生鏽？為什麼需要討論這個？**」為主題生成簡報。
- 「你想到的事情要跟它講，越清楚越好；最好請它多問幾個問題，你一一回答——就像之前 Vibe Coding 一樣。」

### 5.4 用 Obsidian 瀏覽 wiki

- Karpathy 等很多人都用 **Obsidian** 看這種 wiki：**open vault**（開啟資料夾）→ 選專案資料夾。
- Markdown 檔會排得很可讀（不然直接看 .md 有點吃力），數學符號也能正確呈現。示範看了〈認知卸載〉〈認知卸載與專業生鏽〉等頁面。

### 5.5 把滿意的做法做成 Skill

- 來回討論、試做到滿意時就說：「**請把這一個做成 skill。**」
- 你好不容易跟它討論出來（可能要好幾次）的美好風格，希望這次、下次、永遠的簡報都一樣——**Skill 就像你的 SOP**，以後做簡報都照這個 skill 去做，不會這次做成這樣、下次又是另一個樣子。
- **Skill vs. AGENTS.md**：Skill 可以只用在這個專案，也可以用到別的專案；AGENTS.md 則完全是針對這個專案。

### 5.6 示範成果（影片約 2:06 起）

- 這次「盲猜」只看描述就選了**日系手帳**風格（其實可以先讓它把三個範例做給你看）。做出的 HTML 簡報有上一頁／下一頁切換，數學式子也很漂亮，「相當了不起」——等於把你想學的東西做出來給你看。
- 美中不足：明明要求整理相關文獻，這次**沒有做出來**。可能它覺得那一篇（討論專業生鏽）已經解決了所有問題；要多測試幾次才知道它到底有沒有照意思做，沒有的話之後再修改就好。
- 唯一沒示範的步驟：滿意後請它把做投影片的方法**打包成 skill**。
- 「大家如果剛剛有一點點沒懂，不要太擔心，**自己去動手就會發現，比老師說的還要簡單多了**。」

## 06. 本週作業（依上課說明整理）

- 用 AI Agent 工具開一個**專案資料夾**，讓 AI 幫你生成**一份或很多份**網頁／簡報，主題自訂：喜歡的電視劇、某個韓團、台北好吃的東西、你的 AI 日報……
- 💬 老師舉例：**咖啡店清單**。每次發現一家不錯的店（下次一定找不到），就把簡介貼給 AI，請它找更完整的資料、連結、照片，每家做一頁（含位置、Google Map 連結），至少依行政區分類（大安區、中山區……）。做成地圖呈現較複雜，比較適合期末專案。
- 根目錄**一定要有 `index.html`**，連到每次生成的新網頁；每生成一頁，就由 **AI 自己更新** index.html——教它怎麼做就好，不用自己打開編輯器去改。網頁和筆記也都是它做的。
- 可以從 LLM Wiki 開始做，也可以不用；若用 LLM Wiki，知識庫不需要放太多資料，但像示範只放一篇 paper「明顯是不可以的」。
- 上傳到 **GitHub**，要放**完整的專案**（包括 CLAUDE.md／AGENTS.md 這類檔案），不能只上傳 index.html 和做出來的網頁——外行看熱鬧，只會看到你的「台北最好的咖啡店」；助教和老師要看得到**你是怎麼設計出來的**。（上傳步驟可參考〈把作品放上 GitHub Pages：給新手的上傳指引〉）
- 工具選擇：付費版 ChatGPT（Work）、Claude（Cowork）、學生免費的 Gemini（或 Antigravity，見結語）、OpenWorker＋開源模型皆可。

## 💬 閃電秀：Google DeepMind 的 SIMA（影片約 2:12 起）

（一位同學分享；開始前花了一些時間處理投影與聲音設備）

- 論文：Google DeepMind 2024 年發表的 **SIMA**（Scalable Instructable Multiworld Agent）——能在**多款 3D 遊戲中聽自然語言指令行動**的 agent。
- 靈感：語言學習和環境學習互相幫助——語言不是必要的，但能讓 agent **學得更快、更能泛化（generalize）**。
- 五個創新：
  1. 借鏡大型語言模型：資料分佈越廣越好，所以用了很多不同的模擬環境。
  2. 環境刻意設計得很難：多是開放世界遊戲（不會暫停），**只能看螢幕、只能用鍵盤滑鼠操作**，指令用自然語言下。
  3. 用在遊戲上 fine-tune 過的影片模型，取它的**內部狀態表徵**當輸入。
  4. 語言的具象化（grounding）：所有訓練都由語言驅動，用類似人類的同一介面，在多樣環境中學技能。
  5. 希望能泛化：在新環境也要有一定的表現。
- 資料：研究用環境＋多款 3D 開放世界遊戲。人類資料（畫面、指令對應到鍵盤滑鼠動作），收集方式有兩種：玩家自由遊玩後再標註指令；雙人模式（一人下指令、一人執行，共用一個畫面）。
- 架構：從頭訓練的 Transformer＋兩個預訓練模型——**SPARC**（處理圖文，把影像細節對應到文字）、**Phenaki**（影片預測模型，理解畫面接下來怎麼變）；再經 Transformer-XL（結合記憶）與 policy network 輸出動作。影片 encoder 用遊戲影片 fine-tune，其他部分用 **behavioral cloning** 模仿人類。
- 評估：研究環境可直接驗證；遊戲畫面多用 **OCR** 判斷任務是否完成；其餘由人類評分。
- 結果：
  - 各環境成功率約三到六成；停下、開車等簡單動作很穩，建造、戰鬥、採集等複雜的只有約兩成。
  - **有泛化**：留一個環境不訓練直接測，零樣本表現約是專家 agent 的九成。
  - **預訓練模型有幫助**：把 SPARC、Phenaki 換成從頭訓練的 ResNet，表現明顯下降。
  - **語言有用**：拿掉語言輸入，表現大跌。
  - 任務本身就很難：在 No Man's Sky 上，人類也只有約 60% 成功率，SIMA 約 34%。

## 💬 助教時間：第三週作業回顧——呆萌型 AI 機器人就是函數（影片約 2:26 起）

**為什麼要回顧？** 改作業發現，很多同學點子很棒、甚至很偉大，但**功能太強了**——大家從 ChatGPT 開始認識 AI，覺得 AI 無所不能。這次回到最基本的神經網路：它究竟在做什麼？（「今天比較像數學課，用手寫比較有感覺」）

### 函數是一本「答案本」

- 左邊（定義域）是**問題**，右邊（值域）是**答案本**：每個問題都要能在答案本找到答案。
- 數字的例子：

| 輸入 | 輸出 | 對應規則 |
|---|---|---|
| 3、5、−2 | 6、10、−4 | 乘以 2 |
| ±3、±5 | 9、25 | 平方 |
| (3, 5)、(2, 6)、(−1, 7) | 8、8、6 | 兩個數相加（輸入可以是一組） |

- 生活中很多東西也是函數，**不一定是數字**：
  - **生肖**：輸入出生年 → 12 個選項之一（細一點還要月日，因為切分點跟農曆有關）。
  - **星座**：輸入年月日 → 星座；要算上升等詳細星盤，還要出生時間和地點（經緯度）。→ **依你要問的問題，決定要哪些輸入和輸出。**
  - **人格測驗**：問卷每題的答案 → 幾種人格之一。
- 以上這些都是**有表可以查**的。

### 為什麼手寫辨識需要「訓練」？

- 第二週作業的 28×28 圖片，在機器眼中只是一串亮度數字（大部分是 0，經過筆畫的地方才有 120、125……）。機器不知道那是數字，我們**強制訓練**它：這串數字對應到 4（one-hot encoding：十維向量的第 4 個位置是 1，其他是 0）。
- 這種對應關係**沒有表可以查**，所以才需要神經網路。

### 什麼才叫「訓練」？

- 很多同學以為「把一串東西丟給 ChatGPT、讓它變成我要的風格」就是訓練——**不是**。
- 訓練是**調整神經網路的參數**，讓輸入對應到我們想要的輸出。
- 例：100 → 212、25 → 77、0 → 32、10 → 50。用一個神經元（先不放激發函數）$f(x) = wx + b$：
  - 一開始參數亂給，例如 $w = 5,\ b = 30$；
  - 透過 loss function 知道 $w$ 太大要調小、$b$ 太小要調大……
  - 最後調到 $w = \frac{9}{5},\ b = 32$，就完全正確——這就是**攝氏轉華氏**。
- 手寫辨識也一樣：你架的那幾層、密密麻麻的神經元參數，經過訓練被修正，讓**沒看過的資料**也能得到理想結果，這才叫訓練。

### 把題目縮小成可以訓練的小環節

- **高爾夫揮桿**：「輸入一段影片，告訴我扭腰過快……」太複雜。可以簡化成「輸入一張揮桿照片 → 它在 8 個 checkpoint 的哪一個階段」（有協會收集了 1500 多位選手的資料，有訓練素材），之後再做第二階段：判斷什麼叫過早、太慢。
- **分辨兩個長得很像的藝人**：符合作業規定，但要想想它對你的生活是否真的有意義。
- **好例子**（之前「設計思考與人工智慧」課、LLM 出現前）：台大校園的 YouBike 站點，有時滿車、有時一車難求。
  - 輸入：星期幾（課表固定，取星期一到五）、時間、目前車數、降雨機率……
  - 輸出：**半小時後**的空車率，分成 0–20%、20–40%……五個區間（one-hot）。
  - 用途：讓公司知道要不要把車子調走或補車。
- 結論：作業三很多同學**方向沒有不對，只是輸入輸出沒寫清楚**，或功能想得太大。找出可以轉換成明確輸入、輸出的小環節，就能把資料丟進作業二寫好的模型，**真的去訓練**。

## 💬 結語：Gemini 桌面版的限制與 Antigravity（影片約 2:57 起）

- 不論 Gemini、Claude 或其他工具，都要用 **App 版（桌面版）**才能碰到你自己電腦裡的檔案。
- 壞消息（依上課當時的說明，方案可能變動，請自行確認）：
  - 有同學發現 Gemini 的 **Windows 版不行**；
  - 助教說 Mac 版也要到 **Pro** 方案才可以，Plus 還不行。
- 替代方案：Google 的 **Antigravity**。
  - 看起來比較「可怕」、比較有技術感（像終端機），但**用法基本上一樣**：一樣是跟 AI 對話、一樣的指令和討論方式。
  - 甚至不用先自己開資料夾，進去後在任何地方開一個新資料夾，就是你的工作資料夾。
  - 比較大的差別：Antigravity 預設會讀的檔案叫 **`GEMINI.md`**（寫成 AGENTS.md 再叫它讀應該也可以，但建議照它的規範）。
- 有付費、想要比較親切可愛的介面，可以選 ChatGPT 或 Claude；但 Antigravity 其實也沒差很多，只是第一次用比較可怕，用久了就不怕了。有問題可以找助教或老師討論。

| 名詞 | 說明 |
|---|---|
| Agentic AI（代理式 AI） | 能自己多步驟完成交辦工作的 AI；從「問 AI」變成「交辦給 AI」 |
| AI Agent | 教 AI 用你做事的方法做事；AI Agent = AI Model + Harness |
| Harness（工作裝備） | 包在模型外、讓它能「動手」的一切：工作環境、工具、連接器、技能、規則檔、排程 |
| Harness／Loop／Graph Engineering | AI Agent 時代的新名詞；後兩者可視為 Harness Engineering 的一種 |

| 專案資料夾 | AI 有存取權限的工作範圍，專案相關檔案都放在裡面 |
| `CLAUDE.md` | Claude 專用的「員工手冊」（規則檔），作用就是 system prompt |

| 連接器（MCP） | 別人寫好的工具，讓 AI 連上 Gmail、行事曆、雲端硬碟、LINE 等 |
| 排程 | 時間到了讓 AI 自己開工，例如每天早上做 AI 日報 |
| 沙盒（Sandbox） | AI 自己的工作電腦環境，可存檔、跑程式 |

| OpenWorker | 開源的專案型 AI Agent 工具，可搭配開源模型（如 Ollama） |

| raw／wiki／`index.md` | 原始資料資料夾／整理後的 wiki 頁面／所有 wiki 內容的索引 |
| Obsidian | 瀏覽、編輯 Markdown 知識庫的軟體，Karpathy 等人用來看 wiki |
| Farzapedia | 用 LLM Wiki 方法、由多年日記做成的個人化 Wikipedia |
| 可解釋性 | 能看懂 AI 為什麼找到這些資料；LLM Wiki 比 RAG 的抽象向量更容易判斷 |

| Behavioral cloning | 模仿人類示範資料來學習行動的方法 |
| 函數（答案本） | 每個輸入（問題）都對應到一個輸出（答案）的關係 |
