## 01. 文字生成 AI 的原理（投影片 P2–P21，影片約 0:01 起）

### 1.1 自然語言處理與呆萌 AI 機器人（P3–P5）

- **NLP（Natural Language Processing，自然語言處理）**：處理正常人類語言的 AI。
- 現代的 AI 模型只是一個「**呆萌 AI 機器人**」（也就是**函數學習機**）：我們要告訴它**輸入是什麼、輸出長什麼樣子**。
- **AI 最重要的是「問個好問題」**：深度學習專注在「我們怎麼問這個問題？」；整個判斷由電腦做，所以一般要**大量資料**。

💬 老師補充：
- 自然語言就是可以直接輸入我們本來要說的話，不用用很特定、很特殊的方式輸入。
- 政大呆一布 AI 共學實驗室的「五大問題」，第一大問題就是：**為什麼現在的 AI 模型只是一個呆萌型 AI 機器人？**而且「它只有呆，沒有萌」。

### 1.2 對話機器人是怎麼訓練的？（P6–P10，影片約 0:08 起）

- 直覺想法：對話機器人不就該用「客戶說的話 → 客服人員的回覆」來訓練？——**但這樣設計會有問題**。
- 結果「看到答案大家都驚呆了」：**就是用前一個字預測下一個字的模型**（輸入 $x_t$ 目前的字，輸出 $x_{t+1}$ 下一個字）。
- 這樣**世界上所有句子都可以拿來當訓練資料**。例如「炎龍老師很帥」可以拆成：(炎→龍)、(龍→老)、(老→師)、(師→很)、(很→帥)。
- **但這不是個函數！**「今天天氣很好。」拿去訓練，會出現 $f_\theta(\text{天})=\text{天}$ 又 $f_\theta(\text{天})=\text{氣}$——同一個輸入對應兩個輸出。

💬 老師補充：**客服機器人的悲劇**
- 用銀行的客服對話紀錄當訓練資料，聽起來很有道理，而且比大部分同學的作業合理，因為輸入、輸出很明確。
- 問題是**每個客戶說的話長度都不一樣**，客服的回覆也不一樣長，函數不能「一下輸入兩個字、一下輸入五個字」。
- 那就切成固定長度，輸入 15 個字、輸出 20 個字？訓練好、開記者會宣布 24 小時客服專線。第一位客戶很有禮貌地說「你好」，AI 回答：「**不好意思，你沒有說到 15 個字，麻煩你再說一次。**」——第一天就被客訴。
- 語音的部分可以假設用別的模型做語音辨識、再用別的模型把回答轉成語音，你的 AI 機器人本身是純文字就可以。
- 正確答案完全符合呆萌型 AI 機器人的水準：**輸入一個字、輸出一個字**。但電腦看不懂字，就跟八哥辨識一樣，它不知道自己在看鳥，只看到一堆數字進來。
- 「**現在的 AI 就是呆萌型 AI 機器人**。如果你只學到這件事情，出去就可以打趴 80% 其他學 AI 的人。」
- 「今天天氣很好」這種一對多的資料不是函數，函數學習機會非常困惑，最後把所有可能的字拿來「平均」，固定接某個字，那個字對不對也不知道。**不能拿不是函數的資料去訓練函數學習機。**

### 1.3 實際上用的是「有記憶的」神經網路（P11–P15，影片約 0:19 起）

- 前面的字 $x_1,\dots,x_{t-1}$ 的「**記憶**」會融合成一個向量 $h_{t-1}$，和目前的字 $x_t$ 一起輸入，預測 $x_{t+1}$。
- 用神經網路打造這個機器人：建一個個隱藏層、每層放若干神經元，放法差不多「**3+1 種**」：DNN（標準全連結）、CNN（圖形辨識很強）、**RNN（有記憶的結構）**、**Transformers**。
- 可以想成是「**一堆字（prompt）預測下一個字**」的模型，然後就可以一路接下去（P13–P14）。
- 例（Tulu 3 70B）：炎龍老師很 → **幽** → **默** → **。**（P15）

💬 老師補充：
- 還是一個字預測下一個字，但**把前面看過的字的記憶一起放進來**。例如輸入第 10 個字時，把前 9 個字的記憶一起放進來，感覺就像看了 10 個字。前面的字不同，後面接的字就不同，這樣就合理了。
- 「記憶」聽起來匪夷所思，其實就是**某一個隱藏層輸出的向量**。它在計算時會參考前面的記憶，所以我們才把它叫做記憶。
- 簡單說，它**一個字一個字讀，但會記得前面發生了什麼事**，所以前面可以是 5 個字、20 個字、100 個字都沒關係。
- 偉大的 ChatGPT、Claude、Gemini，**基礎模型就是做這件事**。現在跟 2022 年 ChatGPT 剛出現時**沒有差別，還是這樣訓練的**。知道原理，就不會害怕「世界變得這麼快、AI 越變越厲害」。
- 每次只預測一個字，再把它丟回去預測下一個字，所以可以**不定長度的輸入、不定長度的輸出**。
- 以「炎龍老師很＿」為例：它唯一的任務就是**接下去，而且要順**。前面明明在說炎龍老師，下面就不能突然變成「炎龍律師」。它也不知道我是國中、大學還是數學老師，它所有的線索只有「這個人是老師」。**任何它覺得順的就接下去，跟事實沒有關係。**

### 1.4 模型其實是把每個可能的字評分（P16–P19，影片約 0:25 起）

- 電腦只會處理數字，所以**每個可能生成的字都給一個編號**（例：帥 87、幽 94、有 112、熱 174、受 211）。
- 模型替每個字打分數，再經 **softmax**（指數轉換 → 計算佔比）變成機率：

| 字 | 帥 | 幽 | 有 | 熱 | 受 |
|---|---|---|---|---|---|
| 分數 | 1.40 | 0.03 | 1.71 | −0.73 | 0.95 |
| 指數轉換 $e^x$ | 4.05 | 1.03 | 5.53 | 0.48 | 2.59 |
| 佔比 | 30% | 7% | 40% | 4% | 19% |

- **語言模型不知道它在做什麼**，只覺得下一個字放什麼「順」就放（P19）。

💬 老師補充：
- 編號是示意（「這是唬爛出來的」），每個模型的編號規則都不一樣。中、英、日、法、德文都要會，所有字都要給編號。
- 進去的是兩個向量：**現在這個字換成的向量**，加上**前面那堆字的記憶**，對它來說就是一堆數字。
- **softmax 是我們人為做的**（第二大重點）。模型原本給的是 1.40、0.03、1.71 這種分數，百分比是我們經過指數轉換算出來的。你出去怎麼騙人我沒意見，但自己一定要知道。
- 跟八哥辨識不一樣的地方是：**通常不抽最高分，而是用這個機率去抽一個字**。所以每次抽的字不一樣，機率低的字還是有機會被抽到。
- 如果每次都選最高分，你覺得寫得不好、叫它重新生成，它又生出一模一樣的句子，「越看越火大」。為了讓變化性高一點，才從機率分佈去抽。
- 「**人類的幻覺比生成式 AI 的幻覺還要嚴重很多**」——不要再幻想它真的很聰明。它覺得 87 號字很適合，就輸出 87，「它不是在罵我」。

### 1.5 小總結（P20–P21，影片約 0:30 起）

- 文字生成 AI 只是**預測下一個字的呆萌型 AI 機器人**；訓練目標就是把它訓練成「**很會接話**」的**唬爛王**。
- 了解原理，就能用好 ChatGPT 等 LLM：**提供足夠的資訊**、**清楚的指引（要做什麼）**。

💬 老師補充：
- 每次看到一個偉大的 AI 模型，一定要看清楚**它的輸入是什麼、輸出是什麼**。設計整個 AI 系統時，只要舉出其中一個呆萌型 AI 機器人，幫你解決其中一部分就好，不用解決所有問題。
- 訓練時就是希望它當**唬爛王**，不要變成**句點王**（看到不會的就不說話）。所以不能抱怨它唬爛，只能想辦法修正。例如介紹自家產品時，不能讓它唬爛出根本沒有的功能。
- **下 prompt 只有兩個重點**：
  1. **把正確的資訊都提供給它**。早期的 ChatGPT 問到最近的事，會說「訓練資料只到某個時間」；現在的 AI 會偷偷上網搜尋。不管是我們給、還是 AI 自己搜尋，都要有足夠的資訊。
  2. **很清楚地告訴 AI 要做什麼，不要讓 AI 猜**，不要留給它幻想的空間。就算是創作小說這種希望天馬行空的任務，要求還是要說清楚。

## 02. RNN 和變形金剛（投影片 P22–P31，影片約 0:34 起）

💬 老師補充：這是**下週的主題**，本週只很快地預告。Transformer 剛好跟變形金剛同名，所以老師都叫它變形金剛（正式中文好像叫「轉換器」）。**現在幾乎全部都用 Transformer。**

### 2.1 兩種有記憶的神經網路（P23–P26）

| 名稱 | 中文 | 特色 |
|---|---|---|
| **RNN** | 遞歸神經網路 | RNN 層會導入上次的記憶 $h_{t-1}$；RNN 神經元其實和正常的一樣，只是多了「上次的記憶」這組輸入 |
| **Transformer** | 變形金剛 | Google 提出，**一次生成**各時間點的記憶 |

- **RNN 的缺點是遞迴型的運算**：要先算出 $h_t$ 才能算 $h_{t+1}$，沒辦法平行化（P26）。

💬 老師補充：
- 為什麼挑這一層的輸出當記憶？「**就真的是我們高興**，沒有其他理由。」
- 記憶寫成 $h_t$，就是 **hidden state（隱藏狀態）**。這層有幾個神經元，就輸出幾個數字。例如兩個輸入加上兩個神經元上次的輸出，就好像有四個輸入，運算方式跟以前一樣。
- 在 AI 和數據分析的世界，**寫迴圈幾乎是一種「罪」**。「世界上最討厭人家寫迴圈的就是黃仁勳」，因為 GPU 是平行運算，迴圈沒辦法用平行運算加速，你買了最貴的 GPU 也沒什麼好處。
- （老師順帶賣關子：Goodfellow 在介紹 GAN 的演講上，曾被一位大師舉手說「我的學生十年前就做出一樣的東西」。這位大師做了一個跟 RNN 有關的重要模型，下週揭曉。）

### 2.2 Transformer：一次生成各時間點的「記憶」（P27–P31）

- 輸入 $x_1,\dots,x_T$，一次生成 $h_1,\dots,h_T$，分別用來預測 $x_2,\dots,x_{T+1}$（P27）。
- **每個字生出 Q、K、V 三個特徵代表向量**——其實只是做線性轉換：$q_i=x_iW^Q$（$W^Q$ 是學習來的；Google 深愛列向量，所以矩陣乘在後面）（P28）。
- **Self-attention**（P29）：
  - $e_j=q_ik_j^T$ 是 attention 的強度（Google 風是用**內積**）；
  - $e_1,\dots,e_T$ 經 softmax 得到 $\alpha_1,\dots,\alpha_T$；
  - 最後 $h_i=\alpha_1v_1+\alpha_2v_2+\cdots+\alpha_Tv_T$。
- 整個過程基本上是**矩陣乘法**（P30），最後就是有名的 Transformer 公式（P31）：

$$
\text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^T}{\sqrt{d_K}}\right)V
$$

- $d_K$ 是 key 向量的維度；其實除以自己定的一個數就好，「這樣寫增加神秘感……」。
- 詳細推導在第 05 講。

💬 老師補充：
- Transformer 的想法很簡單：**這些字其實已經一起輸進去了**，何必假設一定要讀完第一個字才讀第二個字？乾脆想一個有道理的**平行運算**方式，同時產生每個位置的記憶。
- 而且它不只參考前面的字，**連後面的字也一起考慮**（上下文都考慮），比 RNN 更進一步。最重要的還是**可以平行化運算**。
- 下週看到矩陣就自動昏倒也沒關係，想盡辦法維持清醒聽完，至少會得到一個結論：**發生的事情全部都是算出來的。**

## 03. 生成模型為什麼這麼厲害呢？（投影片 P32–P47，影片約 0:43 起）

### 3.1 Andrej Karpathy 的名作（P33–P37）

- 2015 年部落格文章〈**The Unreasonable Effectiveness of Recurrent Neural Networks**〉（<http://karpathy.github.io/2015/05/21/rnn-effectiveness/>），**引發大家對文字生成 AI 興趣的名作**。
- **RNN：AI 數學家**——電腦產生代數幾何介紹 "Stacks" 的片段，「電腦覺得自己是個數學家！」（P34）
- AI 生成的「**莎士比亞**」作品（P35）。
- **看完一本《紅樓夢》的 AI**：《紅樓夢》生成器（可調 temperature，越小生出的字越固定、越大越隨機）（P36）。
- Prompt「自孫悟空從石頭中蹦出來之後……」，生成出賈政、鳳姐、劉姥姥都登場的「紅樓夢風」文字（P37）。

💬 老師補充：
- **Karpathy 的經歷**：當時在史丹佛念博士班，指導教授是 AI 界很有名的李飛飛。兩人開了一門 **CNN 的課程**放在 YouTube 上，在學習資源還很少的年代，很多人都是看他們的影片學 AI 的。他是 **OpenAI 的創始成員之一**，畢業後到特斯拉發展無人駕駛，ChatGPT 出現後回到 OpenAI 一陣子，之後出來做 AI 教育。老師說他最近到了 Anthropic（做 Claude 的公司）。
- 那篇部落格文章引起轟動，大家開始覺得 RNN 很有趣，當時很多人介紹 RNN 的圖都是抄他的。
- **Stacks**「簡直是為我準備的例子」：念數學博士也有某種「階級」，學代數幾何就像當兵當海軍陸戰隊，感覺很高級。Stacks 又是代數幾何裡比較抽象的概念，大部分念數學的人都不會。AI 讀的是 **LaTeX 檔**，對它來說全是一堆符號，輸出的 LaTeX 是 AI 自己打的，Karpathy 幫它編譯。
- **AI 莎士比亞**真的抓到寫劇本的要訣：一個人說一大段，下一個人接著說，大家輪流說話。單句看起來有點像人寫的，但整個讀起來不知道在說什麼。有趣的是，它不是我們手把手教的，過去的莎士比亞作品裡很可能沒有任何一句一模一樣，**它真的可以創造一些東西出來**。
- **紅樓夢生成器**是過去學長姐寫的。Prompt 跟訓練資料一點關係都沒有（孫悟空根本不在紅樓夢裡），它也能接下去。句型、角色都很像紅樓夢，但整段讀起來不知道在幹嘛。

### 3.2 Karpathy：AI 生成的都是「幻覺」（P38–P40，影片約 1:01 起）

- Karpathy 在 2015 年的文章中，把 AI 生成的叫 **hallucinated（幻覺的）版本**；**LLM 是「作夢的機器」**。
- **幻覺是 LLM 最偉大的特點**（P39）：
  - 從某種意義上來說，幻覺正是 LLM 所做的全部，它們是作夢的機器。
  - 搜尋引擎是 0% 的夢境，但不會創造。
  - 人們實際上的意思是：不希望一個 LLM **助理**發生幻覺。
  - LLM 沒有「幻覺問題」。**幻覺不是一個錯誤，它是 LLM 最偉大的特點。**
- **文字生成 AI 的小總結**（P40）：訓練上就是要「很會接話」；白話文說就是把它訓練成「唬爛王」；AI 生成的叫「幻覺」版本；**幻覺有可能是對的、有可能是錯的，甚至無所謂對錯**。

💬 老師補充：**為什麼要把 AI 生的都叫「幻覺版本」？**
- 這跟現在大部分人用「幻覺」的方式不一樣，但老師覺得 Karpathy 的說法比較有道理。
- **照片的類比**：AI 生成的照片已經像到快分不出來，但我們永遠不會因為「很像」就說那是真的照片。我們不能對照片那麼嚴格、對文字那麼鬆散。
- 好處一：你知道是 AI 生的，就知道**可能有問題，要自己檢查**。
- 好處二：生成的東西**不只是對或錯**。例如寫得一點都不流暢、爛透了，但沒有說錯任何事，這時說它「沒有幻覺」，好像它是很好的 AI，聽起來就怪怪的。錯誤還是可以說它錯，但生成的東西一律當成幻覺。

### 3.3 震驚世界的 GPT 唬爛王系列（P41–P45，影片約 1:05 起）

- OpenAI〈Better Language Models and Their Implications〉：著名的「**發現獨角獸**」唬爛文章（P41）。
- **GPT-2 參數量 15 億**（紅樓夢生成器約 300 萬）（P42）。
- **GPT-3：1,750 億參數**，大到無法下載，只能申請 API 使用，唬爛功力前所未見（P43）。
- **正常人一生讀多少字？**（P44）各家 AI 答案不同（ChatGPT 算錯；Gemini 說 10 億、Claude 說 3 億、Grok 說 2–2.5 億），總之差不多 **2 億字**。GPT-3 大約精讀了 **4990 億**字，一般人要活 9415 次才能達成！
- **只是預測下一個字，但看過超級多東西**（P45）：人類一輩子讀的字大約是 **1B（10 億）量級**；**Llama 3 大約用了 15T 量級**的訓練資料，是人類一輩子的 **1.5 萬倍**。**現代的 LLM 大概什麼都讀過了，所以什麼話都會接。**

💬 老師補充：
- 早期大家還想不到預測下一個字的模型實務上能做什麼，頂多想用來寫制式報告（如財報），或寫摘要（以前還有很高深的理論）。現在 ChatGPT 什麼都會做。
- **獨角獸 prompt**：科學家在南美洲的**安地斯山脈**發現了一整群會說流利英文的獨角獸。超級唬爛，但 GPT-2 接得非常順，寫得就像真正的新聞報導：文法很好、結構完全是新聞的結構，連哪個大學、哪個教授領軍、說了什麼話都有。（老師說以前曾把它講成「美國的安地斯山脈」，是生涯兩大汙點之一，這次是 ChatGPT 糾正的。）
- OpenAI 當時擔心 GPT-2 被有心人士拿去做假新聞，所以**最大的模型一開始不敢公開**，後來才公開。15 億參數在當年是「**大到可怕的模型**」，到了 GPT-3 已經是 1,750 億，完全碾壓。
- **ChatGPT 算錯的例子**：它假設每天讀 30 分鐘、每分鐘 250 個字，卻說一年讀 27 萬字（實際上 $30\times250\times365\approx274$ 萬字）。看起來超有道理，但它**算數學完全憑感覺**：覺得接「2」很順就接 2，覺得接「7」很順就接 7。叫它重新生成一次，答案又會換。
- **LLM 基本上不會算數學**，它沒有在做數學、沒有思考，也沒有去查過去的資料，唯一的任務就是接得很順。
- 不管哪個模型說的，就算是 Gemini 樂觀地說 10 億字，跟 4990 億還是差非常多。不要說一輩子讀不完，連《鬼怪》、《來自星星的你》的主角都活得不夠久。
- 順便記一個重要單位：**10 億就是 1B**。以後看語言模型的大小，常用「幾 B」來衡量。

- 五大商業模型：**ChatGPT**（OpenAI）、**Gemini**（Google）、**Claude**（Anthropic）、**Grok**（xAI）、**Muse Spark**（Meta）。

💬 老師補充：

## 04. 選字的溫度（投影片 P48–P64，影片約 1:16 起）

### 4.1 輸入和輸出的樣子其實不同（P49–P51）

- 「前一個字預測下一個字」的生成模型，輸入和輸出通常是不同類型：
  - **輸入**：通常是某種代表向量（**word embedding**）。
  - **輸出**：**可能的字有幾個，就是幾維向量**（每個字一個分數）。
- 先討論輸出：模型把每個可能的字評分，經 softmax 變成機率（同 P17–P18）。

💬 老師補充：文字模型跟八哥辨識模型「真的八七分像」。八哥辨識輸入照片，文字模型輸入的是文字轉成的數字，對 AI 來說都是數字。輸入聽起來比較高級，叫 word embedding，「解釋完就知道沒什麼高級的」。正確答案是 one-hot encoding，但 AI 輸出的是每個字一個分數。

### 4.2 選字原來也是有學問的（P52–P55）

- 隨機選字的策略，大概有調整 **temperature、top-k、top-p** 等方式。
- **最重要的是依機率抽樣**：若 a、b、c 的機率是 0.7、0.29、0.01，就是 70% 選 a、29% 選 b、只有 1% 選 c（P53）。
- **注意 softmax 是「贏者通吃」**：分數 4.3、3.4、0.2 → 0.7、0.29、0.01，原來前兩名分數感覺沒差那麼多！（P54）
- **關鍵在做了指數轉換**（P55）：

$$
a'=e^a,\ b'=e^b,\ c'=e^c,\qquad a\ \text{經 softmax 轉換為}\ \frac{a'}{a'+b'+c'}
$$

💬 老師補充：temperature、top-k、top-p 是有些 AI 應用場合讓你調整的小參數。**temperature 最匪夷所思，但最重要**；top-k 跟 top-p 第一次看會一頭霧水，名字感覺很像。分數 4.3 跟 3.4 差不多，經過 softmax 卻差了一倍，「有點太過分」。這在八哥辨識沒問題（反正都選最高分），但換成依機率抽樣，選到 b 的機會就被壓得太小了。

### 4.3 用 temperature 來調整（P56–P58，影片約 1:20 起）

$$
a'=e^{a/\tau},\quad b'=e^{b/\tau},\quad c'=e^{c/\tau}
$$

- $\tau>1$ 會**拉近**彼此的機率（更隨機）；$\tau<1$ 機率**更拉開**（生成文字更固定）。

| logit | $\tau=1$ | $\tau=2$ | $\tau=0.5$ |
|---|---|---|---|
| a = 4.3 | 0.70 | 0.57 | 0.86 |
| b = 3.4 | 0.29 | 0.36 | 0.14 |
| c = 0.2 | 0.01 | 0.07 | 0.00 |

- **事實上大型語言模型通常不用擔心**（P58）：LLM 輸出的可能字很多，最終大家分數都不高、很接近 0；分數接近 0 時，exp 函數接近線性，「贏者通吃」不明顯。
- **常見設定**：實務上 $\tau=1$ 很常見，就算要隨機一些也只設到 $\tau=1.1$；反而有時希望每次輸出比較一致時，會把 $\tau$ 設成較小的數字。

💬 老師補充：
- **為什麼叫「溫度」？**老師一直很納悶，後來問 ChatGPT 得到的理由：物理上溫度越高，粒子亂動得越多，**隨機性越強**；溫度越低，移動越遲緩，隨機性越低。
- **關鍵點是 1**：除以 1 等於沒調，就是模型原來的隨機性。除以 2，分數都被拉到 0 的附近，那裡的指數函數很像斜率是 1 的直線，所以比例比較接近原來的分數。
- **什麼時候調低溫度？**例如 AI 解釋法律條文，不能這個人問是這樣、下一個人問又是那樣。客服也是，跟第一位、第二位客戶說的不一樣，就會被客訴「我朋友去問，你居然跟我講不一樣的答案」。
- **logit**：學統計的同學知道 logit 有它的意義（下次請統計學得很好的助教解釋）。在 AI 的世界，它基本上是個「騙人的字」，**看到 logit 就是指輸出的那串分數**（例如 4.3、3.4、0.2）。
- 要隨機一點時也不用調太大，大概 1.1，免得奇怪的字被生成。

### 4.4 top-k 與 top-p（P59–P63，影片約 1:26 起）

- **不管如何，機率低的還是有可能被選到**，於是時常不知在亂說什麼……（P59）
- **top-k**：只選前 $k$ 名（例如 $k=50$）（P60）。
  - 問題：有時可能的輸出非常少。例如「政大應數系教我們生成式 AI 的老師是蔡炎」，下一個字**必須**是「龍」。
- **top-p**：先決定一個機率 $p$（例如 0.9），從機率最高的字開始加，加到 $\sum_{i=1}^N p_i>p$ 為止，**只選前 $N$ 個字**（P61）。
- **Redistribution**：前 $N$ 名的機率加起來通常不是 1，於是做「好高級」的 redistribution——其實就是最簡單讓加起來等於 1 的計算：$p'_k=p_k/P$，$P=\sum_{i=1}^N p_i$（P62）。
- 最讓人驚訝的是 top-p 很晚才出現：正式名稱叫 **nucleus sampling**，是 AI 頂會 **ICLR 2020** 的文章（Holtzman et al., *The Curious Case of Neural Text Degeneration*）（P63）。

💬 老師補充：
- **機率低的字為什麼危險？**訓練資料太多，沒辦法找人一一檢查，所以會學到錯字或不順的字。它們機率雖低，還是可能被選到。一旦選到，後面為了配合前面的錯誤就**越錯越多**，開始胡說八道。
- **top-k 的問題**：有學生推薦老師的課時一時忘了名字，把「蔡炎＿」接錯字，AI 就學起來了。前 50 名一定會把這種錯字包進去，然後「不幸地被選到」。
- **top-p 的例子**：假設 95% 的人都說對「蔡炎龍」，「龍」的機率是 95%，第一個字就超過 90%，所以只會選這一個字。如果加到第五個字才超過 90%，就選前五個。
- 這種「看起來有點白痴的方法」，大家可能以為上個世紀就有了，其實 **2020 年才有人做出來**，還發表在 AI 頂會 ICLR。這也給大家一些信心：**找到一個好的切入問題，搞不好真的以前沒有人想過。**

### 4.5 總之文字生成是一堆字生一個字的模型（P64）

$$
P_\theta(w_i\mid x_1,x_2,\dots,x_T)
$$

- 生成模型就是用前面的字，生出一個**機率分佈**，再選一個策略，依此 **sample** 出下一個字（$w_i$ 是字庫裡的第 $i$ 個字）。

## 05. 尋找特徵的小任務（投影片 P65–P83，影片約 1:31 起）

### 5.1 輸入比較複雜一點（P66–P69）

- 輸入基本上也可以用 **one-hot encoding**：每個字有個編號（例：的 1、一 2、了 3、是 4、我 5），代表向量就是那個位置是 1、其他是 0。
- **但 one-hot encoding 後還是只是個編號！**最主要希望輸入**帶點文字的「意思」**（P68）。
- 想給一個字（或詞）比較有意義的「**特徵代表向量**」，這樣的模型就叫 **word embedding**。但事實上**我們根本不知道什麼是「好的」代表向量**（P69）。

💬 老師補充：第一次學會覺得有點抽象、有點神奇，「但一點都不神奇」。one-hot 只是寫得比較複雜的編號，3 號字跟 5 號字有什麼關係？沒有意義。神奇的是：**我們根本不知道正確答案，也找不到訓練資料，卻要訓練出這個模型**，到底怎麼做到的？

### 5.2 提升 AI 素養到下一個層次的秘密（P70–P75，影片約 1:33 起）

- 這是「**Level 2 的 AI**」（P70）。
- 假設有個訓練得很好的**八哥辨識 AI**（輸出三種八哥的機率 0.70、0.15、0.05）（P71）。
- **每一層神經網路把輸入轉為另一個 tensor**：第 1 層隱藏層放一堆神經元，輸出通常是一個向量；上一層的輸出就是下一層的輸入，如此不斷下去（P72–P73）。
- **每一層的輸出，都可以當成電腦對輸入的理解**——這就是代表那隻土八哥的「特徵代表向量」（P73）。
- 既然最後能正確辨識是哪種八哥，中間的數字可以當成很好的輸入特徵代表向量，常被稱為輸入的 **embedding**（P74）。
- **代理任務（Pretext Task）**（P75）：讓電腦做一些「要懂輸入才能完成」的小任務。這不是最後的真正目標，而是**為了訓練出好的表示向量**。要嵌入到幾維（例如 $N=128$），就在中間隱藏層放 128 個神經元。

💬 老師補充：
- 懂了這件事，**AI 素養就會提升到第二層次**。第一層次（Level 1）就是上週作業：真正清楚 AI 就是呆萌型 AI 機器人。（老師再次提醒：Level 1 的作業真的沒有很難，做錯的唯一原因是把它想得太複雜了。）
- 不管中間是 DNN、CNN 還是 RNN，**任何一個隱藏層的輸出**，都可以當成 AI 對輸入的**抽象理解**。
- 人類解說員會說：土八哥的嘴是象牙白、全身是黑色的。AI 理解了什麼我們看不懂，但**因為它最後能正確分類，所以我們覺得中間那個理解是很好的理解**。
- 直接訓練「輸入一張照片 → 輸出它的理解」是不可能的，因為做不出訓練資料。所以我們訓練的是標準的八哥辨識（代理任務），**真正要用的是前半段的 embedding model**。
- 文字也一樣：**「前面的字預測下一個字」本身就是一個需要理解文字才能完成的小任務**，下次會看到它真的可以當成代理任務。

### 5.3 Word2Vec 的兩種小任務（P76–P80，影片約 1:39 起）

| 模型 | 任務 |
|---|---|
| **CBOW** | 用**周圍的字**（$x_{t-2},x_{t-1},x_{t+1},x_{t+2}$）預測**中間的字** $x_t$ |
| **Skip-Gram** | 用**中間的字**預測**周圍的字**（「會不會更厲害？」） |

- 訓練成功後，**某層隱藏層的輸出就當 embedding**（P77）。
- 訓練完電腦好像「**真的有懂**」：**相似的字會在一起**（Google 官網：<https://code.google.com/archive/p/word2vec/>）（P79）。
- **標準的火力展示**（Mikolov et al., ICLR Workshop 2013）（P80）：
  - 巴黎 − 法國 + 義大利 ≈ 羅馬
  - 國王 − 男人 + 女人 ≈ 皇后

💬 老師補充：
- Word2Vec 是 Google 做的，顧名思義就是把一個字轉成特徵代表向量。
- 哪一個訓練出來的 embedding 效果比較好？答案是**比較困難的那一個**：用中間的字預測旁邊的字（Skip-Gram）。
- 小任務不一定要這兩個。只要是**需要理解文字才能達成的小任務**，都可以拿去訓練，再把中間某個隱藏層當成理解。
- 很多機器學習、自然語言處理的課介紹 word embedding 時一定會講 Word2Vec，常講得「玄之又玄」，因為畫出來相關的字真的會聚在一起。「國王 − 男人 + 女人 ＝ 皇后」是官方給的例子，所以大家都用這個。
- 重點是它沒有很神奇：設計一個**容易準備訓練資料、又要理解輸入才做得到**的代理任務，訓練成功後取中間的隱藏層輸出。它本身也是個呆萌型 AI 機器人，只是訓練方式特別一點。

### 5.4 權重就是「記憶」、Transformer 的 embedding 層（P81–P83）

- **在 Word2Vec 中權重剛好是「記憶」**：權重也可以是我們日後要用的部分，甚至這一小段網路可以想成是「理解」（P81）。
- 原因很簡單：輸入是 one-hot encoding $x$，$W^Tx=h$ 剛好就是取出 $W$ 的某一列，所以**也可以看成是隱藏層的輸出**（P82）。
- **Transformer 其實有自己的 embedding 層**：用 one-hot encoding 輸入後，會連到自己的 embedding 層，也就是**訓練時會同時訓練 word embedding**（P83）。

💬 老師補充：Transformer 的 embedding **不是另外訓練的**，下次介紹 Transformer 時再詳細說（見第 05 講）。

## 06. Prompt 必殺技！（投影片 P99–P111，影片約 1:43 起）

### 6.1 寫好 Prompt 只有兩個重點（P100–P101）

| 重點 | 說明 |
|---|---|
| **正確的資訊** | 它不知道你腦中的背景——把該給的資料、條件講清楚 |
| **清楚的指引** | 要它做什麼、輸出成什麼樣子、給誰看，講明白 |

- **這次作業其實就是一次 Context Engineering**：從 Chat Bot 到 AI Agent，依序是 Prompt Engineering → Context Engineering → Harness Engineering → Loop Engineering → Graph Engineering；這次作業同時練習了 **prompt engineering 和 context engineering**（P101）。

💬 老師補充：
- 第一次上課提過五個「engineering」。**Prompt engineering（提示詞工程）**就是怎麼把提示詞寫好。**Context engineering** 其實就是做好提示詞工程的第一部分：**怎麼給它正確的資訊**。不一定要自己給，也可以叫電腦去搜尋。
- AI 的原理就是看著你的 prompt、很順地接下去，所以**只要做好這兩件事，出來的結果就會是好的**，就這麼簡單。

### 6.2 了解原理，會成為一個強大的吸收器（P102–P104）

- 網路上有各種 ChatGPT Cheat Sheet、Prompt Frameworks（R-T-F、T-A-G、B-A-B、C-A-R-E、R-I-S-E……）（P102）。
- **自己越強，AI 就越強！**（P103）
  - AI 可以提供客服人員 **20%** 的生產力；
  - 對需要產生文案、翻譯、報告、整理簡報及會議記錄的人，增加 **70%** 的生產力；
  - 程式設計師更提升 **125%** 的生產力；
  - 甚至芥川賞作者九段理江都說她的小說 **5% 是 ChatGPT 寫的**。
- **現代人寫 prompt，真的像作文比賽**：例如 Claude Opus 5 的 System Prompt 非常長——「我……怎麼寫得出這種東西呢!?」（P104）

💬 老師補充：
- 外面看到 Prompt Engineering、Context Engineering 有很多偉大的技巧，**不用害怕**：這些技巧都是要幫你把那兩件事做好，只是分得更細。
- 知道原理，你就能判斷「這個方法很適合我」、「這個太複雜不適合我」，不適合的可以不理它。
- **System Prompt** 就是幫機器人做人設：告訴它要做什麼、規則是什麼（之後打造自己的 AI 機器人時會更清楚）。

### 6.3 和 AI 一起寫 prompt，就是寫 prompt 的必殺技！（P105–P110，影片約 1:47 起）

以「介紹 K-POP 女團 IVE」為例：

| 步驟 | 做法 |
|---|---|
| ① 先試陽春版 | 「請介紹 K-POP 女團 IVE。」→ 會得到一篇中規中矩、沒什麼感情的文章（P106） |
| ② 補充只有你知道的內容 | 用 DIVE（IVE 粉）的角度介紹：出道即巔峰、「完顏團」；首張正規專輯《I AM》宣傳期 Rei 生病、只有五位成員打歌；2024 年登上 Lollapalooza、完成第一次巡演，但氣勢不如從前，還有黑粉攻擊，是有點低迷的一年；2025 年《REBEL HEART》的歌詞呈現 IVE 的態度，振奮了 DIVE 們（P107） |
| ③ 請 AI 訪問你 | 「這樣的主題，你覺得還有什麼可以釐清的地方，可以問我。」（P108） |
| ④ 請 AI 幫忙查證、整理成一個 prompt | 「請依我們以上的討論，再收集一下 IVE 有哪些是 K-POP 女團第一的紀錄，然後請打好草稿（先不要寫文章），把要寫的重點、方向整理好。」以後直接用這個 prompt 指引 AI 寫文章（P109） |
| ⑤ 親自閱讀並修改 prompt | **只要是 AI 生成的，不管是 prompt 還是寫出的成品，一定要好好讀一讀！**（P110） |

💬 老師補充：
- 殺手鐧很簡單：**不要再自己去寫 prompt，就是跟 AI 一起寫**。但不是叫它寫完就結束。
- 以前 AI 介紹 IVE，成員常講錯（有時說 5 個、有時說 6 個）。現在它會偷偷上網搜尋，所以基本上是對的。**但它不知道你想寫哪些點**，就算同樣是 DIVE，每個人想強調的重點也不一樣。
- **第 ① 步的「沒頭沒腦」版本**，老師自己的例子是「簡介政大應數系的蔡炎龍老師」：現在會寫對了，但如果網路上的資訊太少，它就會亂說一通。這個版本可以叫標準版、底線版、**基線版（baseline）**。
- 作業指引其實是 ChatGPT 寫的（老師給它的只有七、九項），**不用背有幾項**，重點是跟 AI 談：
  - 你覺得自己想得很完整，就不用讓 AI 訪問你；你比它清楚的事，也不用叫它查。
  - 寫到一半想確認一些事（例如得獎紀錄），又不想自己查，就叫它去查。
  - 最後把討論結果和查到的資訊**整理成一個 prompt**，叫它先不要直接寫文章。
- **第 ⑤ 步最重要**：**你是老闆，AI 是你的員工**。它寫出來的東西你沒看就送出去，很多慘劇都是這樣發生的。即使是一起討論出來的，也要確認每個點它都有 get 到。沒 get 到就再跟它講一次，小地方就直接改，需要補充的就請它再找資料。

### 6.4 這種小技巧在 Vibe Coding 也很好用（P111）

- 「我知道用 AI 寫程式時把規格寫好，比一直要它改更容易成功；但我不太會寫程式，一開始沒辦法寫那麼清楚的規格啊。」
- 技巧就是：**先和 AI 討論，再請 AI 整理出規格。**

- **助教的提問：輸入和輸出到底是什麼？**這呼應上週作業：
  - 模型是一個**函數**，輸入不能只是「股票代號」，不然同一個代號每次輸出都一樣，不可能這次漲、下次跌。
  - 輸入要寫清楚用了哪些指標。例如**連續 5 天的收盤價 → 5 個輸入**；再加上開盤價 → **10 個輸入**。
  - 輸出可以是最簡單的**漲、跌兩類**，也可以細分成漲 5% 以上、漲 5% 以下、平盤、跌 5% 以下、跌 5% 以上這 **5 類**。

### ② 閃電秀：Hybrid RAG（中央大學同學）

- 參加精誠資訊舉辦的 AI 創新比賽（決賽得獎），分享工作坊與決賽的實作架構。
- **Vector RAG**：把文字切塊轉成向量，計算高維空間的**語意相似度**來檢索，適合概念理解和非結構化文字比對。
- **Vector RAG 的兩大問題**：
  1. **缺乏多跳（multi-hop）推理**：要跨多個資料表追蹤關係時，純向量推不出實體之間的關聯路徑。
  2. **處理不了精確的數值統計、排序**：財務資料只能抓到片段文字，很容易讓 LLM 產生**數值上的幻覺**。
- **Hybrid RAG 雙軌架構**：

| 軌道 | 負責 |
|---|---|
| **Vector RAG** | PDF 法規、作業手冊等**非結構化文本**，提供語意比對和背景說明 |
| **Graph RAG**（知識圖譜） | 把關聯式資料庫、表格轉成「實體—關係—實體」，處理多層關聯追蹤和數值 |

- **實體對齊**：先定義每個節點的 Category 和 **Unique Key**，不同資料表匯入時，同類別、同 Key 的資料會自動合併到同一個節點，避免傳統關聯式資料庫多表 Join 的效能問題。
- 前端用標準 API 串接，回傳**結構化 JSON 並附上來源**（具體的圖譜節點和文件段落），確保回答可以查證。
- **結論**：非結構化的知識給 Vector RAG、結構化的數據給 Graph RAG，兩軌並行能提升整個系統的準確性和推理能力。（同學提到，課程規劃 11 月也會介紹 RAG。）

### ③ 閃電秀：AI RP 角色扮演（台大同學）

- **背景**：《哈佛商業評論》2025 年的 AI 用途調查，第一名竟然是「**治療與情感支持**」。AI 已經不只是工具，也開始提供**陪伴**，而陪伴的需求就形成了新的市場。
- **AI RP（AI Roleplay）的五個特點**：角色扮演（依人格、背景、說話方式互動）、情境互動（在特定世界觀裡對話）、共同創作（使用者的選擇推進劇情）、持續關係（記憶讓故事持續發展）、情緒體驗（沉浸感、陪伴感、情緒價值）。
- **已經有原廠模型，AI RP App 為什麼還能成功？**
  1. **輸出風格**：在模型之外加上品牌規則、系統提示、輸出要求，讓回覆風格和角色一致性跟原廠模型不同。
  2. **App 設計**：頁面更像社交或娛樂產品，整合角色圖片、人格、背景故事和世界觀。
  3. **活動設計**：角色會主動寫信、慶祝節日、發動態、回覆留言，讓角色更「活」。
  4. **長期關係**：把對話紀錄整理成摘要，每次回覆前讀取，長對話也能延續劇情。
  5. **社群**：創作者設計角色，使用者互動、分享，形成角色社群。
- **小結論**：差異在於平台怎麼把模型能力**轉換成完整的產品體驗**。人們願意為陪伴和情緒價值付錢，所以可以轉換成訂閱或付費，是很有潛力的新市場。

### ④ 助教課：上週作業（呆萌型 AI 機器人）解說（影片約 2:26 起）

- 上週是請大家設計 **AI 模型**，**不是做一個完整的 AI 系統**。寫了很多功能、很多願景，但**輸入跟輸出沒寫好的話，最多只有 2 分**。請從想要的功能中，挑一個最好實作的來做。
- 這個模型要**從頭自己訓練**，不是 ChatGPT 那種有強大功能的模型。它不會自己判斷、分析、規劃，**只會從你的訓練集學到你想讓它學的特徵**。訓練集沒寫清楚，你自己也會不知道在做什麼。
- **輸入要很明確地拆成欄位，每個欄位固定，而且能轉成數字**。

| 不清楚的寫法 | 改法 |
|---|---|
| 旅遊機器人：輸入「想去的地區、不想去的地區」 | 把能提供的地區全部列出來，以**序列**輸入：想去是 1、不想去是 0 |
| 交通機器人：交通方式 | 列出公車、火車、捷運等，用 0／1 輸入 |
| 聊天機器人：個性、說話方式、偏好 | 同樣列出選項，用 0／1 的形式客製化 |
| 「AI 會幫你辨識收據、截圖，然後做分析」 | Level 1 的 AI 模型不會自動分析，你傳截圖給它，它也不知道你要幹嘛 |
| 同時輸入文字、圖片、聲音 | **專注於一種輸入**就好 |

- **正確的例子**：
  - **冰箱食材辨識**：輸入照片 → 輸出照片裡有哪些食材（例如番茄、雞蛋、麵包）。資料集是大量**標好食材名稱的照片**。它只認得你標過的食材，你放了雞腿、飯、蛋，它不會告訴你這是「排骨便當」。
  - **口說教練**：輸入音檔 → 輸出口說評分。資料集要大量**由真人評過分的音檔**。
- 不知道輸入、輸出怎麼定義的話，可以在 office hour 找助教。

### ⑤ 助教課：怎麼把 prompt 下好（影片約 2:34 起）

- AI 常常「唬爛」你，其實是因為**你沒講清楚需求**，它只好亂生成一些文字來滿足你。
- **AI 就像一個不太懂你的同事**：分派工作只丟一句很簡短的描述，他只會滿臉問號，然後開始亂做，做不好你又生氣。
- **下 prompt 之前沒想法怎麼辦？**
  - 直接跟 AI 亂聊：「我想做什麼，但沒有想法，可以幫我想幾個方向嗎？」它會生出 A、B、C、D、E 各種想法，沒有喜歡的就繼續追問。
  - 請 AI **當你的顧問問你問題**：它通常會列出像心理測驗的選擇題，依你的選擇收斂出方向（Claude 現在就常用這種方式回覆）。
- **交代需求的四個方向**：

| 方向 | 例子 |
|---|---|
| **目標** | 要做報告、分析題目、整理文章…… |
| **背景**（AI 需要知道什麼） | 幫什麼課程做報告；你是大學生還是教授 |
| **額外要求** | 要發在 FB 上，口語化、接地氣、加特定 emoji、字數限制 |
| **格式** | 沒要求通常是文字；可以指定簡報、PDF、程式碼 |

- 需求**不用一次講完**，可以在聊天過程中慢慢加，AI 也會慢慢優化。
- **示範**：只說「幫我寫一個二手市集活動的文案」，AI 就自己猜，生出版本 A、版本 B，還說哪個適合 IG、哪個適合 FB。如果一開始就寫好需求，可以**減少來回的次數**，也比較省 token。

### ⑥ 助教課：實作——讓 AI 做個人網頁、放上 GitHub Pages（影片約 2:40 起）

- **網頁的三個組成**：**HTML**（最基本的元素）、**CSS**（決定好不好看；沒有 CSS 就像很多學校網站，按鈕方方正正、大紅大綠）、**JavaScript**（互動效果，例如點按鈕有回饋、跳轉）。今天只做靜態網頁。
- **步驟**：
  1. 請 AI 生成「呆一布」的個人資料（「它這邊就開始幫我唬爛」），複製下來。
  2. 開新的對話窗，請它生成呆一布的個人網頁。沒有指定風格時，AI 會從關鍵字猜：資料說是數學系，它就猜要「科技感、嚴謹」的風格（助教覺得生得有點醜，因為沒先講好要什麼）。
  3. 到 GitHub **建立新的 repo**（沒付費的話要設成**公開**，個人網頁才會被看到）。
  4. 按 **Create new file**，檔名**一定要叫 `index.html`**，貼上網頁程式碼，按 **Commit**。
  5. 到 **Settings → Pages**，Branch 選 **main**，按 **Save**，等它建置完成。
- 建置好就有一個公開連結可以分享，上網搜尋也找得到，等於有一份**公開的履歷或作品集**。
- 這個做法只適用**單頁的 HTML**；想要功能更多的個人網站，要再跟 AI 討論怎麼做前端。（課堂上建置還沒完成就下課了。）

## 名詞對照表

| 名詞 | 說明 |
|---|---|
| NLP（Natural Language Processing） | 自然語言處理；處理人類正常語言的 AI，輸入就是我們本來要說的話 |
| 呆萌型 AI 機器人 | 函數學習機；只會學一個固定輸入、固定輸出的函數，不知道自己在做什麼 |
| 預測下一個字 | LLM 的核心任務：看完前面的字，替下一個可能的字評分並選字 |
| Prompt | 提示詞；我們輸入給語言模型、讓它接下去的那段文字 |
| Hidden state（$h_t$） | 隱藏狀態，就是神經網路的「記憶」，某個隱藏層輸出的向量 |
| RNN | 遞歸神經網路；一個字一個字算，要先算出 $h_t$ 才能算 $h_{t+1}$，無法平行化 |
| Transformer | 變形金剛；Google 提出，用 self-attention 平行生成各位置的記憶，現在幾乎都用它 |
| 唬爛王／句點王 | LLM 的訓練目標是很會接話（唬爛王），而不是遇到不會就不說話（句點王） |
| 幻覺（hallucination） | Karpathy 把 AI 生成的都叫幻覺版本；幻覺可能對、可能錯、甚至無所謂對錯，是 LLM 最偉大的特點 |
| GPT-2／GPT-3 | OpenAI 的模型；GPT-2 有 15 億參數（獨角獸文章），GPT-3 有 1,750 億參數 |
| LLM（Large Language Model） | 大型語言模型；訓練資料量大、參數量也大 |
| 1B／1T | 1B＝10 億，1T＝1 兆；常用「幾 B」表示模型大小 |
| 五大商業模型 | ChatGPT、Gemini、Claude、Grok、Muse Spark（Meta AI） |
| Logit | 在 AI 世界指模型輸出、還沒經過 softmax 的那串分數 |
| Softmax | 指數轉換後算佔比，把分數變成加起來是 1 的機率；有「贏者通吃」的特性 |
| Temperature（$\tau$） | 溫度；分數先除以 $\tau$ 再做 softmax。$\tau>1$ 更隨機、$\tau<1$ 更固定，關鍵點是 1 |
| Top-k | 只從機率最高的前 $k$ 個字裡選 |
| Top-p（nucleus sampling） | 從最高機率開始累加到超過 $p$ 為止，只從這些字裡選（ICLR 2020） |
| Redistribution | 只留前 $N$ 個字時，把它們的機率重新除以總和，讓加起來等於 1 |
| One-hot encoding | 只有一個位置是 1、其他是 0 的向量；本質上只是編號，沒有意義 |
| Word embedding | 把字轉成帶有意思的特徵代表向量 |
| 特徵代表向量 | 任何一個隱藏層的輸出，都可以當成 AI 對輸入的抽象理解 |
| 代理任務（Pretext Task） | 容易準備訓練資料、又要理解輸入才做得到的小任務，用來訓練出好的 embedding |
| Word2Vec（CBOW／Skip-Gram） | Google 的 word embedding 模型；CBOW 用周圍字預測中間字，Skip-Gram 用中間字預測周圍字（效果較好） |
| Level 1／Level 2 AI 素養 | Level 1：清楚 AI 就是呆萌型 AI 機器人；Level 2：懂得用代理任務取得 embedding |
| 開源 LLM | 可以下載自己跑的模型，例如 GLM、Kimi、Qwen、Gemma |
| VRAM | 顯示卡記憶體；決定能跑多大的模型（Mac 的 unified memory 可直接當 VRAM） |
| LM Studio／Ollama | 在自己電腦跑開源 LLM 的工具（圖形介面／終端機介面） |
| Prompt／Context Engineering | 提示詞工程（把提示詞寫好）／脈絡工程（給模型正確的資訊） |
| System Prompt | 幫機器人做人設：告訴它要做什麼、規則是什麼 |
| 基線版（baseline） | 和 AI 一起寫 prompt 的第一步：沒頭沒腦的陽春版 prompt |
| Vector RAG／Graph RAG／Hybrid RAG | 用向量語意檢索／用知識圖譜檢索／兩軌並行的檢索增強生成 |
| AI RP（AI Roleplay） | AI 角色扮演；以陪伴、情緒價值為核心體驗的 AI 應用 |
| GitHub Pages | GitHub 的免費網頁託管服務；單頁網頁的檔名要用 `index.html` |
